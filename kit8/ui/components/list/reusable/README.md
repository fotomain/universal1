# ReusableList

`ReusableTable`'s functions for rows shown as **items**, on iOS, Android and the web, for **big lists**. Plan and decisions: `documentation/ReusableList_WBS.html`. Demo: route `/demo/list/reusable` (media posts in both data modes, or 1 000 / 10 000 / 100 000 / 500 000 generated rows).

    <ReusableList
      entityName="mediaPostReusable"                 // SystemMetaData key
      listOwnerGUID={ownerGUID} listParentGUID="empty"
      visualColumns={columns}                        // the SCHEMA: item text (listRole), search, sort, filter, validation, export, edit card
      reusableListDataMode="serverDataMode"          // 'clientDataMode' (default) | 'serverDataMode'
      orderDirection="desc" itemHeight={72}
    />
    // a list needs a parent with a height (flex: 1)

## The two data modes (`reusableListDataMode`)
| | `clientDataMode` (default) | `serverDataMode` |
|---|---|---|
| rows in memory | all rows of the scope (redux entity, or `localRows`) | only the loaded pages (`serverPageSize`, default 100) |
| search / filter / sort | on the device (`listEngine.buildView`, search text cached per row object) | in the database (`serverQuery.ts`: PostgREST `or(ilike)`, `ilike`, `eq`, `gte`, `order`, `range`); search starts 300 ms after the last key |
| count | rows.length | `count` of the first page (`serverCount`: exact / estimated / planned) |
| next rows | - | `onEndReached` loads the next page |
| writes | redux sagas (optimistic, Undo) | the same sagas; the loaded rows are patched by hand |
| realtime | yes (as the table) | **no** - the refresh button reloads |
| select all | "all except" store (instant for any size) | the loaded rows only |
| reorder | any position | not AFTER the last loaded row while more pages exist |
| limits | ~100 000 rows in memory; **web: ~236 000 rows** (see below) | any size; archive and Undo of a delete are not available |

serverDataMode reads `SystemMetaData[entityName].tableName` through the Supabase client with the user's session (RLS decides what is read). **No SQL is needed**: it uses the existing table. A register with 500k+ rows should get its own view / RPC later (the plan, W11).

**Width** (`reusableListWidth`, px): not set = the list is as wide as its parent but **at most 960 px** (centred when the parent is wider); set = exactly that width, never wider than the parent, also centred. A wrong value (0, negative, NaN) counts as not set. Rule in `reusableListWidth.ts` (`reusableListWidthStyle`), test `__tests__/ui/list/reusableListWidth.test.ts`.

Web scroll limit: a browser scroll element cannot be taller than 33 554 428 px (Chrome / Edge) or 17 895 697 px (Firefox). 500 000 rows x 72 px = 36 000 000 px: the last ~34 000 rows cannot be reached (measured in Chrome 156). `webRowLimit(itemHeight)` = 236 111 rows at 72 px; above it the list shows a warning - use `serverDataMode` or a filter.

## Drag reorder (phone and web)
Every item has a ⠿ grip (when the list is in the stored order: no search / filter / column sort, `reorderEnabled`, not `readOnly`). Hold it and drag: a ghost follows the finger, a line shows the drop place, the list scrolls by itself near its top / bottom edge, and on release **one** row is saved (`orderInList` between its new neighbours; ascending and descending lists are both handled). Cost does not depend on the list size: only index math over a **fixed item height** (`itemHeight`) - nothing is measured per item.
`reorderController.ts` (pure, tested with fake timers) · `ReorderHandle.tsx` (a `PanResponder` on the grip alone: the list does not scroll under the finger; same code on iOS, Android, web). Row menu commands (Move up / down / first / last) stay.

## Rules
- No state of a ROW inside an item (FlashList recycles the cell for another row): selection and "dragged" live in `listStores.ts`, each item reads only its own flag.
- An item is display only; the edit card (`EditRowModalCard`) or `onRowOpen` edits. `renderItem(row, { grip, ... })` replaces the default item.
- `maintainVisibleContentPosition` is off: after a drop the viewport stays where it is.
- Web: the list scrolls by setting `scrollTop`; devices use FlashList `scrollToOffset`. While the browser pane / tab is hidden no scroll events are fired (that is the browser, not the list).

## Toolbar (`ReusableListToolbar.tsx`, 2026-11-24)
Every menu of the toolbar (More, Sort and filter, card size) opens **right under its own button** (`useMenuAnchor.ts`: the right edge of the menu under the right edge of the button; measured at layout and at the press) - not at a fixed place of the window.
Icons only - the name of an icon is its tip, never text next to it; an icon the list does not need is not drawn: search · **Add (+)** · **ring button** (2026-11-26: switches the select-rows column on / off, like the ring of the web card list: at the LEFT edge of every row an arrow up, a round check box and an arrow down (`RowSelectColumn`; the arrows = the row menu's Move up / down, dimmed at the ends and while a search / sort / filter is active), outside a custom card too; **web: a GHOST POINTER** (`GhostPointer.web.tsx`, 2026-11-26): a page cannot move the real mouse pointer, so after an arrow moved a row the real pointer is hidden over the page (a transparent layer, `cursor: none`) and a drawn pointer jumps one row with the arrow and follows the mouse; the next press goes to what is UNDER THE GHOST (an arrow of the list = pressed again, anything else - the select-all circle, a toolbar button - = THAT element is pressed; inside the list the ghost STAYS over it, outside the list it goes); Escape / wheel / 5 s idle remove it; iOS / Android: nothing; under the toolbar the strip with the round SELECT-ALL circle on the SAME vertical line, empty / − some / ✓ all, a press on a full one clears; off at the start, `selectionVisibleAtStart` = on; off again clears the selection; not drawn without `selectionEnabled` / when read only) · **card size** (only with `cardSize`) · **Sort and filter** (the column menu, sorts / filters of the columns) · reload (serverDataMode) · `toolbarExtra` · **More (⋮)** (Export, Share). Under it the chips of the active sort / filters and the selection strip. **Narrow bar** (2026-11-26, `isNarrowToolbar`, `TOOLBAR_NARROW_WIDTH` 640 px, measured with `onLayout` of the bar - the width of the list, not of the window): row 1 = title + search, row 2 = ALL the buttons (`-bar-row-search`, `-bar-row-buttons`); a wider bar keeps the one row. Measured in Chrome at 440 px on `/catalog/project`.
- **Add**: `CreateElementForm` (a component, props `CreateListElementFormProps`) = the Add button opens it in a window over the list (`ReusableListCreateModal`); the form hands a `rowJSON` to `onCreateFirst` or `onCreateLast`; its three dots icon (top right) = Export / Share of the typed data (the same formats as the More menu), the list makes the row at the top / end of the SHOWN list (`source.createAt(index, rowJSON)`), closes the window and scrolls to it. Without the prop Add makes an empty row (or calls `onAdd`). The Media Posts list uses `forms/CreateListElementForm` (origin types, see `kit8/ui/components/list/forms`).
- **Scroll buttons** (`ScrollToLastUsedCardButton`, `ScrollTopButton`, `ScrollBottomButton`, before More): the last used card = the card pressed / opened, whose menu / FAB command ran (`state.actions.*`, `markUsed`), dragged or just made by the Add form; the button is off while there is none (or it is filtered away) and scrolls so that card is in the middle of the list (fixed item height = index math). Top / bottom scroll to the first / last item. The toolbar row wraps on a narrow phone.
- **Card size**: `cardSize` + `onCardSizeChange` (+ `cardSizes`) show the button `cards/SelectCardSizeIconButton` (menu cardSmall / cardMedium / cardBig, the current one checked). The HOST owns the value and sets `itemHeight` from it (`cards/cardSize.ts`: 96 / 192 / 400 px) - an item has a fixed height.

## Swipe actions + the Settings of a list (`reusableListGUID`, 2026-11-26)
**Every ReusableList has an inner id, `reusableListGUID`** (a required prop: a constant string per list that never changes, e.g. `mediaPosts.list`, `demo.reusableList.generatedRows`; it falls back to `entityName:testID` when missing). The **local settings** of a list (`ReusableListSettings`, `reusableListSettingsStore.ts`) are kept **on this device** under it (AsyncStorage key `reusableListSettings:<guid>` + memory; no SQL, no per-user copy). They are changed in the window **three dots menu of the toolbar -> Settings** (`ReusableListSettingsModal.tsx`, loaded when first opened; Reset = defaults; every choice is saved at once). Not offered when the list has `swipeActions={false}`.
- `swipeModeFromLeftToRight` (the finger moves left -> right; default `archiveWithStop`) and `swipeModeFromRightToLeft` (default `deleteWithStop`), each one of: **archiveWithStop · archiveWithDesappear · deleteWithStop · deleteWithDesappear** (any mode in either direction, also the same twice).
  - **...WithStop**: the card stops at the 96 px button (Archive orange / Delete red) however far it is dragged; press the button. A press on the open card closes it.
  - **...WithDesappear**: a short swipe (>= 48 px) opens the button, a long swipe (30 % of the width) or a flick past 58 px runs the action at once and the card slides out. An archive that hides rows keeps the card out; a delete asks first (user setting), the card returns if answered Cancel.
- **`showArchivedRowsMode`** (radio in the window): **`showArchivedRowsOnSeparateTab`** (DEFAULT) = archived cards leave the main list and live on their own tab: tabs **All** (the cards that are not archived) and **Archived** (`-tab-all`, `-tab-archived`, `ScrollableTabBar`), drawn **only while archived cards exist** (server mode: among the loaded rows; with none, no tabs and everything is on All; the last restored card sends you back to All); an archive / unarchive swipe takes the card out of the tab you are on (it slides out). **`showArchivedRowsInOneList`** = archived cards stay in the one list with the Archive icon, no tabs. A list with `swipeActions={false}` (no Settings item) is always one list. The first version's boolean `showArchivedRows: true` is read as the one list. The swipe modes do not change this.
- **Swipe is ON in every list** (`swipeActions` default on; `false` = none; `{ archive: false }` / `{ delete: false }` switch an action off). `canArchiveRow(row)` = false takes Archive from that row only (Media Posts: file rows, which the table refuses to update). Needs `canEdit` for archive and `canDelete` for delete (a read only list has no swipe). Screen readers get the actions as accessibility actions.
- **Archive writes ONLY `rowJSON.rowIsArchived = true`** (a second archive = `false`) through `source.patchRow` - no archive entity, the row stays where it is (unless hidden, see above). The card shows a small orange **Archive icon** (`-archived-<guid>`, bottom left of the card, on the vertical line of the ⠿ grip); hover (web) / press / long press shows the tip "Archived. Swipe <right|left> to restore." (`PMTooltip`, scope `app`). The mark also shows in a list without swipe. A custom card gets `state.archived`. The existing `source.archive` (move to an archive entity, row menu) is untouched.
- `swipeInset` ({ x, y, radius }): the visible card is inset inside its item (Media Posts: 12 / 4 / 16) - the buttons are drawn exactly under the card.
- Gesture (`ReusableListSwipeRow.tsx`, one `PanResponder` per item, `Animated.translateX`): one open item at a time (`openStore`); a recycled cell resets (guid change); the row menu (long press / right click) is ignored for the row being swiped; PanResponder starts counting `dx` when it takes the gesture, the distance moved before is added back (`lead`). Rules in `swipeModel.ts` (pure: `resolveSwipe`, `clampSwipe`, `swipeOutcome`, `hidesArchivedRows`, `normalizeListSettings`).
- Tests: `__tests__/ui/list/swipeModel.test.ts`, "swipe actions" block of `reusableList.test.tsx` (the buttons + the Settings window, not the finger). Seen in Chrome (demo `/demo/list/reusable`, `/posts/mediapostcrud`): Settings window, Archive with Stop, Archive with Desappear, the All / Archived tabs on the real Media Posts list (one archived post). **Not tried**: iOS / Android fingers, FlashList recycling with an open swipe, a screen reader, the Delete modes in the browser. `/catalog/currency/exchange/list` is still `ListWebCardsComponent` with its own swipe. The demo's "Media posts" list has `swipeActions={false}` (real data).

## Default card functions: FAB + three dots menu + Archive (2026-11-26)
Every custom card (`renderItem`) gets three functions from the LIST, so a card draws none of them: **the three dots menu** (top right, `-itemmenu-<guid>`), **the FAB** (bottom right, `-fab-<guid>`, `CardLocalFab`; the commands of THAT card, only what the user may do: Edit (needs `onRowOpen` / an edit card), Add below / above + Duplicate (not when the list has its own `onAdd`: a host that makes its rows itself, like Projects), Move up / down (stored order only), **Archive / Restore**, Delete; `rowFabModel.ts`, pure) and **Archive** (the swipe, the FAB item and the item of the three dots menu all write ONLY `rowJSON.rowIsArchived`; `state.actions.archive(guid)` for a card's own button). Archive is offered unless `swipeActions` is `false` / `{ archive: false }` (the user's swipe settings do not matter) and `canArchiveRow(row)` is not false; it needs `canEdit`.
- `cardFab={false}` = no FAB (a card that draws its own: the media post card has its own with Play / Open link). `cardFabActions(row, state)` = the host's commands, shown BEFORE the standard ones; give the same commands to `extraMenuItems` so the menu and the FAB agree (Projects: `kit8/catalog/project/projectCommandsModel.ts`).
- The FAB list opens above the button, or below when that has more room; a list that fits on neither side scrolls (`fabListPlacement` of `CardLocalFab`, 8-9 commands in a short window).
- Tests: "default card FAB + the Archive command of the row menu" block of `reusableList.test.tsx` (the `CardLocalFab` is stubbed there), `__tests__/catalog/project/projectCommandsModel.test.ts`, `fabListPlacement` in `mediaPostCards.test.tsx`. Seen in Chrome on `/catalog/project` (the Projects list, 13 real projects, phone and wide layout): FAB list, three dots menu. **Not tried**: archiving / deleting in the real database, a phone finger, a screen reader.

## Cards (a custom `renderItem`)
**Every card has the three dots menu (⋮) at its top right** (2026-11-26): the default item draws it itself, for a custom card the list adds it over the card's top right corner (`-itemmenu-<guid>`, opens the row menu; follows `swipeInset`); a card leaves ~16 px free at its top right for it. Off only with `contextMenuEnabled={false}`. The three dots menu also has **Archive / Restore** (before the host's `extraMenuItems`), see the section above.
`renderItem(row, state)` - `state` = `{ index, reorderable, dragging, grip, actions, canEdit, canAdd, canDelete, canOpen, archived }`; `state.actions` = `edit remove duplicate createBefore createAfter moveUp moveDown makeFirst makeLast openMenu` (stable functions; `remove` asks first, every command checks the user's rights). `renderItemDeps` = anything the item reads from outside (a map of names ...): when it changes the visible items are drawn again (FlashList draws again only when `extraData` changes). `onDeleteRows(ids, rows)` returns the ids that are left for the ordinary delete (a file row is deleted by the files function). `refreshOnFocus` reads the rows again every time the screen is focused (a Drawer screen stays mounted). Cards: `kit8/ui/components/list/cards` (README there).

## Add form: person documents (2026-11-24)
For the origin types **Person - ID card** and **Person - passport** the form `forms/CreateListElementForm` shows `forms/PersonDocumentDataInput.tsx`: the SAME data a scan gives - surname, given names, sex, date / place of birth, nationality, personal number, address, document number, issuing state, date of issue, valid until, issued by, notes - and the **owner photo** ("Attach photo" = file dialog on the web / the picker on a phone, made a small JPEG by `personPhoto.ts`; Replace, Remove). Model (pure, tested): `personDocumentInputModel.ts` - the check (surname, given names and number needed; real dates DD.MM.YYYY; 3 letter states; valid until after the date of issue), the fields in the order of a scan, the rowJSON = the one of the ID reader's post (`idCardFields`, `idCardOwnerName`, `idCardNumber`, `idCardKind`, `idCardFolder`, `mediaImageUri`), so the card, the read only details and the exports work for it. The photo also goes to the file storage `identification/idcard|passport/<post guid>`: the form hands it to the list as an extra, `onElementCreated(guid, rowJSON, extras)` lets the host upload it (`MediaPostsNativeList`; the post is written a moment later than the form closes, so `uploadIdentificationPhotoWithRetry` tries again up to 4 times).
