# Estimation dashboard (`kit8/pm/estimation`)

BUILT 2026-11-24, WEB FIRST (phone layout not done). Design: `documentation/ESTIMATION/dashboard/claude/ESTIMATION_DASHBOARD_WBS.html` (+ `google/`). SQL: **PART 58**.
Route `/pm/project/estimation/dashboard` (`app/pm/project/estimation/dashboard`), Drawer row **Estimation dashboard** right under Project dashboard; Project settings -> Estimation has a button that opens it.
With no project (or after **Change project**) the dashboard shows `ui/EstimationProjectPicker`: the user's projects of the active organization to pick, and **Create project** (a new project with the organization's default settings, `permissionCreateProject` needed). The project edited = `?projectGUID` or the selected project; when that project names an estimation project (`projectEstimationGUID`, see `kit8/pm/view/project/estimation`) the estimation project is edited.

## What it does
- **Estimate** tab (2026-11-25): the Project dashboard with the estimate instead of the Gantt chart = `[ task tree of the estimation project | the estimate of the PICKED row ]` (`view/project/tree/PMProjectTreeHost` = the REUSABLE task tree of the Project dashboard (`PMGanttSurface rightPane='custom'` + keyboard + main FAB + the windows the tree opens, see `kit8/pm/view/project/tree`); the project is selected in the PM store like the task window does). A line belongs to a task by `rowJSON.taskGUID`; a leaf task shows its lines and new sections / positions get its guid; **RULE (2026-11-25): an estimate is set on TASKS only** (`canCarryEstimate`: `rowKind` task with no subtasks; never a stage - also an empty one -, a milestone or a summary task): such a row shows the **TOTALS table** instead of the estimate (`ui/EstimationStageTotals`, `stageTotals` of `model/estimationTaskModel.ts`: a line per row below it in tree order, a stage = the sum of its tasks, positions / direct / overheads / profit / base / current / the view currency, then the total; lines with no task are not in it; "Show the whole estimate" brings the sheet back), takes no new position and no "Give the checked lines"; UI / model level only (no SQL guard); nothing picked or the button **Show the whole estimate** = all lines (also the unassigned ones, e.g. an example) and there the button *Give the checked lines to: <task>* sets `taskGUID` (a section takes its positions along); the totals under the sheet are the totals of what is shown. Pure rules: `model/estimationTaskModel.ts`. The board itself (`ui/EstimateSheet`), every cell edited in place, 4 layouts (simple = claude proto_01, advanced = google proto_01 + more), three currencies stored per line (`sumForBudget`, `sumForAccounting`, `sumForConsolidation`), the user switches the shown one (Budget | Accounting | Consolidation).
- **Positions only, the norm is SELECTED** (2026-11-25): the sheet has NO `+ Section` button and no Section column - the hierarchy is the task tree on the left; the bar has `+ Position` (every layout, the trade breakdown too; the line gets the picked task). A position takes its norm from the norm book: the norm column holds a button (`Select norm`, or the code of the chosen norm) -> `ui/SelectNormWindow` (a modal with `NormBookPanel pickMode`: no import / export, the row button reads `Select`) -> `applyNormToLine` writes `normCode`, `normGUID`, the unit and the six unit costs of the norm's priced resources into THAT line (quantity, coefficient, task and a typed description stay; the description is taken from the norm only while empty). The tab Norm books still has `Add to the estimate` = a NEW position with the norm (also in the picked task). The search field of the norm books (also in the picker) asks the DATABASE (>= 3 characters, code or title; trigram GIN indexes `idx_estimation_norm_code_trgm` / `_title_trgm` in start1 - without them the all-books search hit the 8 s statement timeout): with no book picked it searches ALL books (a `Norm book` column shows where a norm is from, each norm is priced by its own book), with a book picked only that book unless the switch `Search in all norm books` is on; the table has no search box of its own. The bar has NO labour rate field (removed 2026-11-25, a norm book has no rate: the labour money of a norm is 0 there, the labour is priced in the estimate). **Labour / unit from / to** = a filter of the loaded norms by their labour cost of one unit (hours x the rate = 0 for now; empty = no border; sections stay). Sections of older documents (examples, imports, `lineKind = 'section'`) are still shown and calculated; new ones cannot be made. Tests `__tests__/pm/estimation/estimateSheet.test.tsx`, `normBookPanel.test.tsx`.
- **Document settings**: title, cipher, price level, method (base prices + index; commercial), indexes, rates (read from the rate book), overheads / profit, contingency, header names, column switches.
- **Norm books** (`ui/NormBookPanel.tsx`): a read only `ReusableTable` with a FOLDERS TREE like the catalogs - World Norms (v2) -> continent -> country -> book -> the sections met so far; the table lists the sections / norms of the picked folder (read a folder at a time, or by the search of the book) with EVERY field as a column (kind, code, title, original title, unit, base type, section type, content, resource count + composition, NR / SP codes, language) and the button Add to the estimate; tree of books: import of FSNB-2022 XML zips (`ImportNormBooks`, source e.g. `/Users/mgtimber/UNIVERSAL1/norm_books/ru`), export zip with csv + json (`ExportNormBooks`); a norm is added to an estimate with its costs (`model/normCosting.ts`).
- **Templates**: example estimates for input and for export. **Summary**: chapters 1 - 12, contingency caps, VAT. **Export**: Excel (own writer on fflate, SUMIF formulas) and PDF (the app's `buildTablePdf`).

## Rules
- Project switch `useGOSTInformationInDocuments` (default false): off = no country-specific text, form number or authority in the screen and in exported documents (`useGOSTInformationOf`, `estimationForms.ts` option `gost`).
- Right `permissionEstimationManager` (SQL PART 58 `perm_my_matrix.canManageEstimation`): the organization administrator and project managers automatically; others read.
- Calculation = ONE implementation (`model/estimationCalc.ts`); the tests of the SQL and of the model use the same golden cases.
- Norm rows are `rowGUID` + `rowJSON` rows; ids are deterministic (`estn-<hash(book)>-<kind>-<hash(path)>`); their translations live in `catalogTranslationTable`; `CatalogTranslationsHost` skips `estn-` rows (read per book).
- RU -> EN translation of the norm text is optional (`import/normTranslator.ts`, Google AI key needed); RUR -> target currency (default EUR) at import.
- Every text is a `pmT` key (14 languages).
