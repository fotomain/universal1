# Estimation dashboard (`kit8/pm/estimation`)

BUILT 2026-11-24, WEB FIRST (phone layout not done). Design: `documentation/ESTIMATION/dashboard/claude/ESTIMATION_DASHBOARD_WBS.html` (+ `google/`). SQL: **PART 58**.
Route `/pm/project/estimation/dashboard` (`app/pm/project/estimation/dashboard`), Drawer row **Estimation Dashboard** right under Project dashboard; Project settings -> Estimation has a button that opens it.
With no project (or after **Change project**) the dashboard shows `ui/EstimationProjectPicker`: the user's projects of the active organization to pick, and **Create project** (a new project with the organization's default settings, `permissionCreateProject` needed). The project edited = `?projectGUID` or the selected project; when that project names an estimation project (`projectEstimationGUID`, see `kit8/pm/view/project/estimation`) the estimation project is edited.

## What it does
- **Estimate** tab (2026-11-25) = the Project dashboard with the estimate instead of the Gantt chart: `[ task tree of the estimation project | ESTIMATE GRID ]`. The tree is `view/project/tree/PMProjectTreeHost` (REUSABLE, see `kit8/pm/view/project/tree`); above it the dashboard keeps the estimate chips, the four layout buttons and the three currency buttons.
  - **The grid** (`grid/EstimateGridPane.tsx`, Skia) is ONE Excel-like sheet with ONE row per tree row, on the SAME vertical scroll value as the tree (`PMGanttSurface` gives `renderRight` the shared `viewport` and the `toolbarHeight`, exactly what the Gantt chart uses: no scroll is synchronised after the fact). Its header is as high as the tree header, so the names of ALL columns stand on one level; the bar above it (totals of the document in the view currency, the two buttons below) is as high as the tree toolbar.
  - **A row**: a TASK (`canCarryEstimate`: a leaf task) = its ONE position (`rowJSON.taskGUID`), typed in place; a stage / milestone / summary task = the read only SUMS of the tasks below it (bold, tinted); a task with several positions (older or imported data) = their read only sum with `n positions` in the description. Lines with no task (an older document, a norm added with no task picked) or whose task was deleted are not in the grid: the bar button *Give the next line without a task to the picked task* gives them one at a time to a task that has no position yet. Examples and imported tables no longer make such lines: they make their TASKS too (see **Templates** below).
  - **Subtotals of a stage by unit**: when every position below a stage (or the several positions of a task) counts in the SAME unit, its Unit and Quantity cells show that unit and the sum of the quantities; with different units or a position without a unit they stay empty.
  - **The columns** = the layout the user picked (`model/estimateGridModel.ts` `gridColumns`; the layouts and the columns the user may hide: `model/estimationLayouts.ts`), minus the columns hidden in the document, with every calculation of that layout (cost elements, overheads, profit, totals, the three currencies, the price of the quick quote, per m2 / share of the trade breakdown); calculated columns are tinted, input columns are white. Calculation = `estimationCalc` (one implementation).
  - **Mouse / touch**: tap = select the cell AND the task row of the tree; double tap = edit; the norm cell is a button (one tap opens the norm books); wheel / drag = scroll (vertical = shared with the tree, horizontal = the grid's own). **Keyboard (web)**: arrows move the cell and the tree row, Enter / F2 / a typed character edit, in the editor Enter commits and goes down, Tab commits and goes right, Esc cancels, Del clears the cell; the keys stop in the grid (the tree's Del = delete the TASK, Tab = indent never see them while the grid has the focus). A task with no position gets one on its first edit (quantity 1).
  - **Column headers work like the ReusableTable's** (2026-11-25): a ▾ button at the right of every header (a tap = the **Filter & Sort** popup `ReusableTableColumnMenu`: sort A→Z / Z→A, Contains / = / ≥ / ≤ / Empty / Not empty); right click / double tap / long press on a header = the menu **Filter & Sort · Clear filter · Clear all filters and sort · Copy header name**; a sorted column shows ▲ / ▼, a filtered one a dot. The grid has ONE row per tree row, so the filter / sort is handed to the TREE through the store (`treeExternalView`, `model/estimateGridView.ts` `buildExternalView`): the rows that match stay (their stages stay as context, collapsed ones are opened), the siblings of every stage are reordered (stage sums are sorted too; empty cells last). It is not saved, it is cleared when the screen loses the focus or the grid goes. **Ctrl / Cmd + F** (grid focused, web) = the find bar inside the table: every cell that contains the text is highlighted, Enter / Shift+Enter / ▲ ▼ walk the matches (the cell and the tree row are selected), Esc closes. NOT built: "Fill all lines" of the header menu, moving / resizing columns, filters / sort kept per project.
  - **List-select cells are hyperlinks**: the norm cell, the option cell (Status) and the catalog cells (budget item, business unit) are drawn in the link colour, underlined, with the pointer cursor, while the cell can be changed.
  - **Words of this dashboard**: the tree toolbar says **+ Section** / **+ Line** (Subsection in the menu) instead of Stage / Task (`ESTIMATION_TREE_LABELS`, `PMProjectTreeHost labels`, `view/tree/toolbars/treeToolbarLabels.ts`); the Project dashboard keeps Stage / Task.
  - **Number cells** are edited with the buttons of the app's number inputs inside the cell: **−** and **+** (one step from what is typed, kept to the column's range) and the **calculator** (OK puts the result in and commits); the editor is EXACTLY as wide as its cell (2026-11-25: it used to be 190 px and covered the next column; the three buttons now shrink in a narrow column, `editorButtonSize`), Esc cancels. After the norm window closes the grid takes the keyboard back.
  - **Text the tree font cannot draw** (the Russian norm books are Cyrillic; translated titles): `grid/useGridFonts.ts` - web: Roboto from `/fonts/Roboto_*.ttf` of the app if you put the files there, else from the CDN of the package (only when such a text is on the screen; the header of the file is checked, a dev server answers an unknown `/fonts/` path with HTML and status 200), native: the system font. The task tree itself still shows boxes for Cyrillic names (Space Grotesk, Latin only).
- **Positions only, the norm is SELECTED** (2026-11-25): the sheet has NO `+ Section` button and no Section column - the hierarchy is the task tree on the left; the bar has `+ Position` (every layout, the trade breakdown too; the line gets the picked task). A position takes its norm from the norm book: the norm column holds a button (`Select norm`, or the code of the chosen norm) -> `ui/SelectNormWindow` (a modal with `NormBookPanel pickMode`: no import / export, the row button reads `Select`) **that STARTS AT the norm the position already has** (2026-11-25: `startAt` = `normGUID` / `normCode` of the line -> `readNormLocation` finds the norm and the sections above it, the window opens its book, the section selected in the tree, the norm row marked and scrolled into view (`focusRowGUID`); the folders tree opens the way to that section and scrolls to it (`revealSelected` of `FolderTreeReusable`, opt-in: the selected folder's ancestors open, also when they arrive later); found by code when there is no GUID; a norm that cannot be found, or a position with no norm, = the usual start) -> `applyNormToLine` writes `normCode`, `normGUID`, the unit and the six unit costs of the norm's priced resources into THAT line (quantity, coefficient, task and a typed description stay; the description is taken from the norm only while empty). The tab Norm books still has `Add to the estimate` = a NEW position with the norm (also in the picked task). The search field of the norm books (also in the picker) asks the DATABASE (>= 3 characters, code or title; trigram GIN indexes `idx_estimation_norm_code_trgm` / `_title_trgm` in start1 - without them the all-books search hit the 8 s statement timeout): with no book picked it searches ALL books (a `Norm book` column shows where a norm is from, each norm is priced by its own book), with a book picked only that book unless the switch `Search in all norm books` is on; the table has no search box of its own. The bar has NO labour rate field (removed 2026-11-25, a norm book has no rate: the labour money of a norm is 0 there, the labour is priced in the estimate). **Labour / unit from / to** = a filter of the loaded norms by their labour cost of one unit (hours x the rate = 0 for now; empty = no border; sections stay). Sections of older documents (examples, imports, `lineKind = 'section'`) are still shown and calculated; new ones cannot be made. Tests `__tests__/pm/estimation/estimateSheet.test.tsx`, `normBookPanel.test.tsx`.
- **Document settings**: title, cipher, price level, method (base prices + index; commercial), indexes, rates (read from the rate book), overheads / profit, contingency, header names, column switches.
- **Norm books** (`ui/NormBookPanel.tsx`): a read only `ReusableTable` with a FOLDERS TREE like the catalogs - World Norms (v2) -> continent -> country -> book -> the sections met so far; the table lists the sections / norms of the picked folder (read a folder at a time, or by the search of the book) with EVERY field as a column (kind, code, title, original title, unit, base type, section type, content, resource count + composition, NR / SP codes, language) and the button Add to the estimate; tree of books: import of FSNB-2022 XML zips (`ImportNormBooks`, source e.g. `/Users/mgtimber/UNIVERSAL1/norm_books/ru`), export zip with csv + json (`ExportNormBooks`); a norm is added to an estimate with its costs (`model/normCosting.ts`).
- **Templates**: example estimates for input and for export. **Summary**: chapters 1 - 12, contingency caps, VAT. **Export**: Excel (own writer on fflate, SUMIF formulas) and PDF (the app's `buildTablePdf`).
- **The task tree is the structure of every output and input** (2026-11-25; there are no section lines any more):
  - **Printed forms** (`export/estimationForms.ts`: local estimate, resource sheet, quotation; Excel + PDF): `model/estimateOutlineModel.ts` `buildEstimateOutline` lists the document in the order and with the outline numbers of the TASK TREE: a stage (a task row with rows below it) = a heading `1.2. Name` with the sum of everything below it, a task = its position (description = what is typed, else the task name), a stage with nothing to print is left out. The Export tab reads the tasks of the project (`createTaskApi(client).readProjectData`) and hands them to `formsFor({ tasks, ... })`; `FormOptions.tasks`. The quotation takes the category of a position from its stage when none is typed. What the tree cannot place (an older document with section lines, a line with no task, a line whose task was deleted) follows under the heading **Lines without a task**, in the order of its own line tree - so the totals of a form always equal the totals of the document (the Excel TOTAL = SUMIF over the numbered positions, headings carry no number). Without tasks (`tasks` omitted) a document is listed flat / by its own sections, as before.
  - **Summary estimate**: unchanged on purpose - it adds the TOTALS of the documents (`summaryRowsOf`), which do not depend on how the lines are grouped.
  - **Examples** (`exampleDocument` -> `{ doc, lines, tasks }`): a stage per section / trade and a task per position; `tasks` is the TASK PLAN (`TaskPlanRow`: parents before children). The dashboard writes the plan into the task tree first (`makeTasks`: `taskRowsFromPlan` + `project_import_tasks`, 400 a chunk, then the tree is read again), then the document with positions that name those tasks (`taskGUID`). A failure after the tasks were made leaves the tasks (delete them in the tree).
  - **Input from a table** (paste / CSV, `estimateFromTable`): one position per row, each on a task of its own named by the description (else the norm code, else `Position n`); the column `section` is the STAGE the task goes under - a stage directly under the project with that name (case does not matter) is joined, every other new name makes ONE stage; no section = the task stands directly under the project. The CSV template keeps its column names (`section` = the stage).
  - **NOT changed because they do not depend on the structure**: the norm books (import of FSNB zips, export zip), the norm cell of the grid, the SQL (the line guard still accepts `lineKind` section for older documents). **Not done**: *Add to the estimate* of the Norm books tab with no task picked still makes a line with no task (it shows under **Lines without a task** in the forms); an import cannot put a row under a stage that is not directly under the project.

## Rules
- Project switch `useGOSTInformationInDocuments` (default false): off = no country-specific text, form number or authority in the screen and in exported documents (`useGOSTInformationOf`, `estimationForms.ts` option `gost`).
- Right `permissionEstimationManager` (SQL PART 58 `perm_my_matrix.canManageEstimation`): the organization administrator and project managers automatically; others read.
- Calculation = ONE implementation (`model/estimationCalc.ts`); the tests of the SQL and of the model use the same golden cases.
- Norm rows are `rowGUID` + `rowJSON` rows; ids are deterministic (`estn-<hash(book)>-<kind>-<hash(path)>`); their translations live in `catalogTranslationTable`; `CatalogTranslationsHost` skips `estn-` rows (read per book).
- RU -> EN translation of the norm text is optional (`import/normTranslator.ts`, Google AI key needed); RUR -> target currency (default EUR) at import.
- Every text is a `pmT` key (14 languages).
