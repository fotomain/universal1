# BUDGET1 — книга «Бюджетирование деятельности промышленных предприятий России» как проект

Источник: К.В. Щиборщ, «Бюджетирование деятельности промышленных предприятий России», М.: «Дело и Сервис», 2001 (электронная версия Word-97 `.doc`, 310 страниц).
Цель: показать процесс планирования и бюджетирования **подробно, через проектное управление** (WBS + диаграмма Ганта + строки затрат / результатов).

## Что получилось

| Файл | Что это |
|---|---|
| `../BUDGET1_BOOK.html` | вся книга в одном HTML (русский): текст, 162 таблицы, **131 рисунок перерисован в HTML + CSS** (57 схем, 11 рисунков-графиков, формулы, малые таблицы), оглавление слева, номера страниц книги |
| `BUDGET1_WBS_DATA.sql` | SQL проекта BUDGET1: справочники + WBS (450 строк) + 818 строк затрат / выручки + 377 связей диаграммы Ганта |
| `BUDGET1_WBS_REPORT.txt` | отчет генератора: все строки WBS с датами и числом линий, проверка денег книги |
| `run_budget1_sql.command` | запуск двух SQL файлов на связанный Supabase (как `RAILWAY_1/run_2_sql.command`) |
| `tools/` | скрипты, из которых все это собрано (повторяемо) |
| `figures_original/` | 131 оригинальный рисунок из `.doc` (для сверки с перерисованными) |
| `../../kit8/docker/test_budget1.sh` | тест SQL на локальном Postgres 15 (docker) |

## 1. Книга в HTML (`BUDGET1_BOOK.html`)

* `.doc` не хранит разрывы страниц и рисунки (macOS `textutil` теряет все 131 рисунок), поэтому `tools/extract_doc.py` читает бинарный файл сам: потоки `WordDocument` / `1Table` (где стоит каждый рисунок), поток `Data` (сами рисунки, PNG и WMF), объекты Equation Editor (формулы).
* **Страницы.** Страница каждого заголовка точна (оглавление книги, 75 заголовков). Серые отметки «стр. N» справа между заголовками — *оценка* (интерполяция между двумя заголовками по объему текста, таблиц и рисунков, веса подобраны методом наименьших квадратов; ошибка ±1–2 страницы). Те же страницы стоят в скобках в названиях WBS.
* **Рисунки** перерисованы заново (не вырезаны): прямоугольники, стрелки (один слой inline-SVG), графики, формулы (`<i>`, `<sub>`, дроби, радикалы). Плотная схема 38 (вертикальный факторный анализ) показана деревом с отступами — так читается и на телефоне. Оригиналы лежат в `figures_original/NNN.png`; рисунок книги № N = `tools/figures/figs_*.py`, `FIGS[N]`.
* Опечатки оригинала не правились (например, в формуле к рис. 27 в обоих слагаемых «на начало периода»; подпись «Схема 37» после «Схемы 32» в главе 6 — так в книге).
* Сборка: `python3 documentation/BUDGET1/tools/build_book.py`; предпросмотр рисунков рядом с оригиналом: `python3 tools/preview_fig.py 17 18 --side`.

## 2. WBS и диаграмма Ганта (`BUDGET1_WBS_DATA.sql`)

**Правила модели (так велено в задании):**

1. **Структура как в книге:** глава = этап, раздел книги = подэтап, **один бюджетный документ (таблица книги) или одна операция (проводка таблицы 26, шаг составления бюджета, этап регламента) = одна задача WBS**. Таблицы 1–120 книги — все 120 стали задачами или частью задачи (табл. 11 напечатана в книге как «Таблица П.»).
2. **Номер страницы** книги в скобках в конце названия: `Составить бюджет прямых затрат труда (Таблица 5) (37)`.
3. **У каждой задачи нижнего уровня есть линии** (вкладки Finances): выручка (= deliverable), материалы, расходы, время ролей. Деньги примера книги (II квартал 2001 г.) лежат в задачах, которые их планируют; остальные задачи несут время ролей (часы условны). Суммы в рублях: **1 000 руб. = 1 тыс. руб. книги**.
4. **Роли и типы ролей** (8 типов, 61 роль со ставками), **статьи бюджета** (10 стандартных из `start4` PART 32 + 6 своих), **бизнес-единицы** (22; организация книги: ПЭУ, ФЭУ, УКС, УМС, бухгалтерия, цеха — центры нормативных затрат, отдел сбыта — центр доходов, центр прибыли …).

**Проверено на деньгах книги** (`BUDGET1_WBS_REPORT.txt`, `test_budget1.sh`):

| Таблица книги | Задача | Линии | Сумма, тыс. руб. |
|---|---|---|---|
| 2 бюджет продаж | 3.2.5 | выручка: А 5000 т × 105,4; Б 1000 т × 164 | 691 000 |
| 6 закупки материалов | 3.6.4 | материал 111: 85 000 кг × 1; 112: 40 000 кг × 2,2 | 173 000 |
| 5 прямой труд | 3.5.1 | 84 000 + 20 000 ч × 2,05 | 213 200 |
| 9 ОПР | 3.8.1 | 8 статей (материалы, труд, энергия, ремонт, амортизация …) | 208 000 |
| 11 ПКР | 3.9.3 | комиссионные, реклама, упаковка, транспорт × продукты А, Б | 38 000 |
| 12 постоянные расходы | 3.10.2 | 8 статей | 57 000 |
| 17 налоги в себестоимости | 3.10.3 | 6 000 + 2 000 + 5 000 | 13 000 |
| 19 инвестиции (приход периода) | 3.13.2–3.13.5 | оборудование, СМР, подряд | 140 000 |

Где книга не дает часов (косвенный труд 90 000, сверхурочные 25 000, зарплата руководства 5 000, служащих сбыта 10 000), часы подобраны так, чтобы сумма равнялась данным книги; строка говорит об этом. Остальные 784 строки времени и все ставки — **условные** (одна ставка книги: 2,05 тыс. руб./ч основного рабочего).

**Диаграмма Ганта.** Даты — *иллюстративный* план одного бюджетного цикла: подготовка и составление бюджета II квартала с 08.01.2001 (глава 3 — до 27.03), исполнение и контроль 02.04–30.06.2001 (операции главы 5 «в течение периода» идут полосами через квартал, «по окончании» ждут веху 02.07), анализ с 02.04, стимулирование после анализа, проект ИСУ (глава 9) с 15.01. Календарь Пн–Пт. Каждая задача зафиксирована «не раньше даты» и связана `FS` с тем, за чем идет (377 связей), поэтому диаграмма открывается ровно как задумано.

**Не сделано (специально):** план линий **не проведен** (Post) — это делает приложение: *Project actions → Post unposted tasks*. Тест проводит все 357 задач через `create_task_line_plan` (4 604 строк плана, итог 1 556 804 300 руб. = сумма линий) — правила бизнес-единиц и статей выполняются.

## 3. Как применить

1. Выполнены `start1_sql_tables.sql` → `start2_sql_code.sql` → `start4_sql_insert_missing.sql` (обычная установка).
2. Запустить `documentation/BUDGET1/run_budget1_sql.command` (или вставить `BUDGET1_WBS_DATA.sql` в Supabase SQL Editor). Файл можно запускать повторно (заменяет проект BUDGET1 с фиксированными GUID, справочники обновляет).
3. В приложении открыть проект **BUDGET1** → Project actions → **Post unposted tasks**.
4. Чтобы владельцем проекта стал конкретный пользователь, впишите его e-mail в `v_owner_email` в начале блока (по умолчанию — владелец самого нового проекта, иначе единственный пользователь).

## 4. Пересобрать

```bash
pip3 install olefile
python3 documentation/BUDGET1/tools/extract_doc.py "/путь/Щиборщ.doc" documentation/BUDGET1/build
python3 documentation/BUDGET1/tools/build_book.py        # документация/BUDGET1_BOOK.html
python3 documentation/BUDGET1/tools/build_wbs_sql.py     # BUDGET1_WBS_DATA.sql + BUDGET1_WBS_REPORT.txt
kit8/docker/test_budget1.sh                              # проверка на Postgres 15 (docker compose up -d)
```

WBS пишется в `tools/spec_*.py` (язык `wbs_kit.py`: `H` / `S` — этап, `T` — задача, `TB(n, …)` — задача таблицы n, `W(...)` — время ролей); справочники — `budget1_catalogs.py`; страница каждого названия ищется по якорю (фраза в начале абзаца книги): неверный якорь останавливает сборку.

## 5. Что неизвестно / ограничения

* Страницы задач — оценка (±1–2), страницы заголовков точны.
* Не проверено на вашем Supabase и в ваших браузерах: SQL проверен на Docker Postgres 15 со структурой приложения, книга — во встроенном браузере (Chromium); даты Ганта пересчитывает клиент приложения при открытии (задачи зафиксированы, результат должен совпасть).
* Формулы Equation Editor (7 штук) и 60 картинок-формул распознаны вручную по изображению; схемы перерисованы по размерам оригинала с точностью до пикселей порядка нескольких процентов.
