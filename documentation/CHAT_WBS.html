Chat

Users talk in themes. A theme lives in a chat object: the personal object of a user (Main) or the object of ONE task of a project. Files and URLs can be attached to a message, files go through the existing file attachments (Google Drive / OneDrive). New messages show as a red number next to the three dots menu of the app bar.

3. Scenarios

Scenario 1 - Main

  1. The user opens the Drawer item Chat (route /chat).
  2. The screen calls chat_main_ensure() once: it creates the chat object of the user (kind user, title "Main") if it does not exist, and returns it.
  3. The list shows the themes the user may see: created by them, or where they have a chatMembersTable row, newest message first, with the unread count; plus the task chats of the user (section 4).
  4. Button New theme opens a window: Title, Description, Message, chatMembers (multi pick of the active members of the organization, may stay empty). Create = ONE call chat_theme_create: the theme, the owner row, the member rows, the first message. The theme view opens with the cursor in the input.
  5. A user sees only themes where they have a member row (the creator has one). Nobody else, also not an administrator (decision Q5).

Scenario 2 - task chat

  1. Task menu -> Create based on this -> Chat (also the line menu and the toolbar icon of the Finances table, like the other documents).
  2. chat_task_ensure(task): if the task has a chat object, return it; else create the object, its ONE theme, the owner row (the caller) and the members of Q2. Idempotent, race safe (the unique key).
  3. The app opens the theme view (a NEW browser window on web, a route on a phone - Q12).
  4. The header shows Title and Description, both live from the task (section 4). The input has the focus, so the user types at once.
  5. The icon Go to Chat in the toolbar of the task CRUD table calls the same function: it creates the chat when the task has none, else opens it.
  6. Visible only while the project switch chatFunctionalityEnabled is not false.

4. The chat of a task: title and description

  • Title = projectInnerPrefix + the task name (the task text rowJSON.taskDescription); Description = the task description, changes in real time. They are never copied into the theme. The list RPC chat_theme_list computes the title with chat_task_title(task) (prefix of the project, one space, task text) and the app reads the task row for the header. A rename of the task or a new prefix is therefore in every chat at once, with nothing to keep in step.
  • The task row has ONE text field in the code (taskDescription) and a free-form notes. Reading: Title = taskDescription; Description = notes (empty = nothing shown). See Q4.
  • Real time: the theme view subscribes to ONE row of project_task_table (rowGUID=eq.<task>, the channel helper of kit8/redux/reusable/createSupabaseTableChannel.ts), so it works also in a new browser window where the project cache is empty. A deleted task removes the chat (C7), the open window shows "This task no longer exists".
  • projectInnerPrefix: 4 letters, stored in upper case in project_table.rowJSON.projectInnerPrefix; a missing value = the first 4 letters of the project name, upper case (computed, not stored). Not required to be unique (the settings field only warns when another project of the organization uses the same prefix).
  • Members of a task chat (owner's answers Q2 / Q13): the creator (owner) + every user of the Time lines of the task - the RACI column, all four items, also when the task is finished. They follow the Time lines automatically: a user who is added, changed or deleted in task -> Time -> RACI joins or leaves the chat at once (statement triggers on task_line_table call chat_task_sync_members; chat_task_ensure does it again). A member from the RACI is removed by changing the RACI; a member added by hand stays when the RACI changes. The people of task_user_permission_table are not used (that table only has open tasks).

5. Files in the chat (built ON the file attachments)

No second file system. A chat file is a file of kit8/files with a new scope chat:

  • Row: a row of mediaPostTable (PART 49): rowOwnerGUID = organization, rowParentGUID = chatThemeGUID, rowJSON.fileSourceKind = chat, fileSourceProjectGUID for a task chat, the storage keys as for every file (googleDriveFileId / oneDriveItemId, fileStorageProvider).
  • Folder (chainFor of the Edge Function, one new branch). Owner's answer Q9: kit8root/chat/user/<userGUID>/theme/<chatThemeGUID>/files/<file> for the Main chat (1111 = the userGUID of the owner of Main); a task chat uses chat/task/<taskGUID>/theme/<chatThemeGUID>/files/<file>. The folders get the same marks as the others (kit8Kind chat / theme, kit8OrganizationGUID). Folder key chat:<themeGUID> (files_authorize tells the function the kind and the user / task guid: chatKind, chatRefGUID) (scopeKeyFor), so the OneDrive prefix rule works unchanged.
  • Storage: a task chat follows the storage of its project (projectFilesStorageProvider), the Main chat follows the organization default (files_provider_of_scope gets the branch for chat). Upload, chunks, signed view link, replace / versions, permanent delete are the existing code.
  • Authorization (files_authorize, new branch for scope chat, GUID = theme): read / add = the caller is a member of the theme; delete / update = the uploader, the theme owner, or an organization administrator; switchOff when the task chat's project has filesFunctionalityEnabled or chatFunctionalityEnabled off. The answer carries maxBytes = the organization limit (below).
  • The same file at many places: a file belongs to the THEME, a message holds a REFERENCE: { fileGUID, url, name, size, mime } where url is the address of the viewer route (app/files/view), never a storage link. Attaching it again = pick it from "files of this theme" (no upload, no copy); the message stores one more reference. Every click, preview and download goes through the URL and the function signs a short link at that moment. The bubble reads the name from the reference, so a renamed or replaced file needs no change in the messages (a new version has the same fileGUID).
  • Deleting: deleting a message never deletes the file. Deleting a file (theme files list) leaves the references; the bubble shows "file deleted" for them.
  • Limit: organizationTable.rowJSON.maximumChatAttachmentFileSize in MB (default 10, allowed 1..100: the 100 MB is the existing phase 1 cap of the file module, MAX_UPLOAD_BYTES). It is checked three times: the app before the upload, the Edge Function before the upload session is issued (min(MAX_UPLOAD_BYTES, maxBytes)), and the message guard trigger (the size in the reference is checked against the file row, not trusted).
  • Who changes the limit: only an administrator or a project manager (a holder of the project manager profile in any project). Today organizationTable is updated by the administrator only, so a save from the Organization form would be refused for a project manager: the field is saved through the RPC chat_set_max_attachment_size (organization_is_admin() OR the project manager profile held anywhere through perm_can with no project). Other users see the value, read only.
  • No storage connected (the administrator did not connect Google Drive / OneDrive): the attach button is disabled with the sentence of the files module; URLs and text still work.

6. URLs

  • A message is: text, and/or URLs, and/or files. A URL is sent inside the text (the app finds http(s):// addresses and makes them links; the model function extractUrls) or separately (button "Add link": address + optional title, shown as a link card; same idea as "Add link" of the Files panel). A link sent apart is stored in rowJSON.urls; a url inside the text is found when the message is shown (so it is not shown twice).
  • Opening: web = a new browser window (window.open(url, '_blank', 'noopener,noreferrer')); phone = a route: an address of this app (/files/view, /pm/project/dashboard?..., /chat/...) is opened with the router, an external address with Linking.openURL (the system browser).
  • Safe: only http, https and the address of this app are links; javascript:, data: and anything else is shown as plain text and never opened. The database also refuses such a scheme in urls.
  • A file reference is a URL like any other (the viewer address), so the same bubble code opens both.

7. Realtime, unread numbers, the red icon

  • Redux entities in kit8/redux/SystemMetaData.ts: chatObject, chatTheme, chatMember, chatMessage (table name, realtime on, match for a scope - the generic read already supports match, orderBy and paging). The realtime channel (createSupabaseTableChannel) feeds the store; Supabase Realtime sends only the rows the RLS lets the user read, so a user never gets another chat.
  • Messages: a theme view reads the newest 50 (match = theme, order created_at descending), older ones on scroll up (Q16). A new message of the user is inserted by the saga with a GUID made by the client: optimistic, and the realtime echo has the same GUID, so it is not shown twice.
  • Unread = the messages of a theme newer than the user's lastReadAt (the member row) that the user did not write. chat_unread_counts() gives the number per theme in one query. The badge number = the sum over the themes the user can see (a task chat of a project with the chat switch off does not count).
  • The icon: a chat bubble button in ApplicationBarApp, placed right before the three dots menu, with a red round number (99+ above 99). It exists while the sum is above 0 and disappears at 0 (the request). Press = the list /chat with unread themes first. The hook useChatUnread starts from chat_unread_counts(), adds +1 for a realtime INSERT of a message of another author in a theme that is not open, and re-reads on a change of the user's own member rows (read on another device).
  • Mark read: while a theme view is focused, the window is visible (AppState on a phone, visibilitychange on the web) and the list is at the end, the app calls chat_mark_read(theme) = lastReadAt := the time of the newest message of the theme (the server time, never the device clock). Messages that arrive while the view is open are read at once.
  • Cost: Realtime checks the RLS policy for every subscriber for every change. The policy of the messages is ONE indexed probe, chat_is_member(rowParentGUID) (STABLE, unique key theme + user) - the bench C19 measures it with many members.
