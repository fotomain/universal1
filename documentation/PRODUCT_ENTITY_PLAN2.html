Write it typed, read it precomputed: product storage built for shop speed

A shop reads products thousands of times for every time it writes one. So this plan stops storing products in one shape for both jobs. It keeps a typed, normalized write model that mirrors WooCommerce exactly. Next to it is a read model: four small tables, rebuilt per product,, holding exactly what each shop screen needs, already filtered, sorted and turned into JSON. Each shop screen costs one database call. At 100,000 products, the listing, the product page and the category facets all answer in under 10 ms.

Measured, not guessed. Both plans were built on PostgreSQL 16 with the same synthetic shop: 20,000 and 100,000 products, 66k and 329k variants, 260 categories, color, memory, size and brand. The category page, the most-visited page of any shop, went from 187 ms to 0.44 ms at 100k products. Facet counts went from 403 ms to 0.24 ms. Details are in Benchmark; the SQL that produced them is in SQL.

Design principles

1 · Pay at write time, not read time

Price ranges, in-stock flags, ancestor categories, search vectors and card JSON are computed once per product change, not once per visitor. A rebuild costs about 1 ms per product.

2 · Hot fields are typed columns

Anything a shop filters or sorts on gets a real column: price, stock, date, popularity, rating. Category and attribute filters use int[] arrays with GIN indexes. JSONB is kept for data the shop only displays and never searches.

3 · Every product has a sellable variant

A simple product gets one default variant, so price and stock live in one place for all product types. Woo still sees simple products; the mapper folds the default variant back into the product.

4 · Integers everywhere they count

Prices are stored as bigint cents, not text or float, so they are exact, fast and safe to sort. IDs are bigint identity rather than text UUIDs, which makes indexes smaller and joins faster. Term IDs are int, ready for intarray.

5 · One screen = one call

The listing, facets and product page each come from one RPC that returns finished JSON. Pagination uses keysets (after), so page 50 is as fast as page 1.

6 · The shop reads only what is published

The read model contains only sellable, published rows. Anonymous visitors call SECURITY DEFINER RPCs, so there are no row-level-security checks on hot paths and no direct table access.

Read model · what the shop reads

Precomputed, denormalized

  • listing: one row per product with card JSON and filter and sort keys
  • variant_facet: one row per sellable variant, for exact attribute filters
  • page: one JSON document per product page, with an ETag
  • category_facet: counts for each category and term

WooCommerce sync (webhooks plus a reconcile using modified_after) and the Expo admin both write only to the left side. The shop (Expo web, a Next.js storefront or anything else) only calls the RPCs on the right.

Read model: one table per question the shop asks

shop.listing: "which cards, in what order?"

  • card jsonb: everything a tile shows (name, image with size and LQIP, price range, regular price, on-sale flag, stock, rating, color swatches). The shop renders it as is.
  • category_ids int[]: the assigned categories plus all their ancestors, searched with a GIN index (gin__int_ops).
  • term_ids int[]: terms of in-stock variants plus product attributes plus brand.
  • price_min/price_max are the effective prices: sale-aware, and counting only in-stock variants when any are in stock.
  • B-tree sort indexes on (price_min, id), (published_at, id) and (total_sales, id) serve "top 24" and keyset pages straight from the index.
  • search tsvector (name and SKUs weighted A, short description B) with a GIN index, plus a trigram index on the name for partial words.

shop.variant_facet: "does an in-stock variant match?"

  • One row per sellable variant: term_ids int[], price, in_stock.
  • This makes "Blue and 256 GB" correct: both terms must be on the same in-stock variant. A product with a blue 128 GB and a black 256 GB doesn't match. Woo's own wc_product_attributes_lookup table solves the same problem.
  • @> (contains all) for single-value groups, && (overlaps) for "Black OR Blue" groups.

shop.page: "everything for one product page"

  • The product, gallery, attributes with terms and swatches, and categories.
  • The variant matrix is keyed by sorted term IDs, e.g. "5-14" → {id, sku, price, regular, stock, qty, media}. Picking a color or memory changes the price and stock on the client with zero requests.
  • etag (an md5 of the document) gives cheap 304 Not Modified responses and cache keys.

shop.category_facet: "what can I filter by here?"

  • Rows of (category_id, term_id) → product_count, plus a price-range row per category (term_id = 0). category_id = 0 is the whole shop.
  • Covers the most common request, a category landing page with no filters yet, in 0.2 ms.
  • Once the visitor adds filters, shop.facets() switches to the live query, which takes 4–18 ms.
Storage cost of the speed: at 100k products the write model is 165 MB and the read model about 310 MB (listing 125, variant_facet 49, page 133). Plan 1's JSONB tables were 345 MB for the same data. That's roughly 1.4× more storage in total. All of it fits in the RAM of a small Supabase instance, which is what keeps the reads below a millisecond.

Storefront API: three calls cover the shop

RPCInputReturns100k products
shop.search(p){category, terms: [[5,6],[14]], priceMax, q, inStock, sort, limit, after}{items: [card…], next: {k, id}, version}0.8–8.5 ms
shop.facets(p)the same filters{terms: {termId: count}, price: {min, max}, source}0.24 ms precomputed · 17 ms live
shop.product_page(slug)slugpage document + etag0.12 ms
  • Sorts: price, price_desc, popularity, date, menu_order, rating. The function builds SQL from a whitelist (no injection) so each sort uses its own index.
  • Filters: AND between attribute groups, OR inside a group. Every group must match the same in-stock variant.
  • Pagination: pass the returned next as after. Keyset pagination stays fast on deep pages and never repeats or skips items when stock changes.
  • Exposure: the tables live in schema shop, which is not exposed by PostgREST. Thin wrappers public.shop_search(p), public.shop_facets(p) and public.shop_product_page(slug) are SECURITY DEFINER, with SET search_path = '' and GRANT EXECUTE TO anon. Being STABLE, they can be called with HTTP GET, which makes them cacheable.
-- public wrapper (one per RPC): anon can call it, cannot touch the tables
CREATE FUNCTION public.shop_search(p jsonb) RETURNS jsonb
LANGUAGE plpgsql STABLE SECURITY DEFINER SET search_path = '' AS $$
BEGIN
  PERFORM set_config('response.headers',
    '[{"Cache-Control": "public, max-age=30, stale-while-revalidate=300"}]', true);   -- PostgREST response header
  RETURN shop.search(p);
END $$;
REVOKE ALL ON SCHEMA shop FROM anon, authenticated;
GRANT EXECUTE ON FUNCTION public.shop_search(jsonb) TO anon, authenticated;

Benchmark: Plan 1 (defTable JSONB) vs Plan 2

The setup was PostgreSQL 16.13 with 2 vCPU, 8 GB RAM and a warm cache. The client ran on the same machine, and each figure is the median of 40 runs. Plan 1 got the indexes a careful developer would add: GIN jsonb_path_ops on rowJSON, GIN on categoryTermGUIDs, expression indexes on price, sales, slug, and a trigram index on name. Both plans return the same row counts for every query. The facet row uses Plan 2's live query; the precomputed category_facet answers the same question in 0.24 ms (see the API table).

Freshness: how changes reach the shop

Write path

  1. An editor saves in the Expo admin through RPC shop.save_product(doc): one transaction that upserts product, variants and links, then calls rebuild_product. The change is visible immediately.
  2. A Woo webhook (product.updated, order.created for stock) arrives at the Edge Function, which updates the write model. Triggers queue the product, and process_dirty() runs right away.
  3. pg_cron every 5 s runs process_dirty(500) as a safety net. It uses SKIP LOCKED, so parallel workers are safe.
  4. pg_cron every minute runs refresh_category_facets() and also queues products whose sale_from/sale_to passed in that minute, so scheduled sales switch on and off on time.
  5. A nightly reconcile with Woo uses GET /products?modified_after=… and rebuilds anything that changed.

The visible lag is about 0 s for admin edits, under 5 s for Woo changes, and under 60 s for facet counts. The counts are a navigation aid, not a promise, so a minute of lag is acceptable.

Realtime: the shop doesn't subscribe to product tables, since thousands of visitors listening to catalog changes would be expensive. The admin keeps realtime on shop.product for editors.

Beyond the database: the other half of shop speed

HTTP / CDN cache

GET RPC responses carry a Cache-Control header with a short max-age and stale-while-revalidate. Put Cloudflare (or an Edge Function cache) in front and use catalog_version in the cache key. The product page answers If-None-Match with its etag.

Client cache

React Query (already in the app) with a staleTime of 60 s. Prefetch product_page(slug) on hover or when a card scrolls into view. Variant switching uses the page's matrix, with no requests.

Images

The card holds w, h and lqip: reserved space and an instant blurred preview. Serve WebP or AVIF at 2–3 widths from a CDN (Woo's own or Supabase Storage transforms), and lazy-load below the fold.

If the shop stays on WordPress: this plan speeds up the Expo or headless shop that reads from Supabase. The WordPress storefront itself is made fast inside WooCommerce: turn on HPOS, keep the product lookup tables regenerated, use a persistent object cache (Redis), use page caching, and use the Woo "filter by attribute" lookup table. These tables are Woo's own version of this plan's read model.

The taxonomy idea from Plan 1 still applies; here it becomes the typed attribute / attribute_term and category tables.

-- ---------- rebuild one product into the read model ----------
CREATE OR REPLACE FUNCTION shop.effective_price(v shop.variant) RETURNS bigint LANGUAGE sql STABLE AS $$
  SELECT CASE WHEN v.sale_price IS NOT NULL
               AND (v.sale_from IS NULL OR v.sale_from <= now())
               AND (v.sale_to IS NULL OR v.sale_to > now())
              THEN v.sale_price ELSE v.regular_price END
$$;

CREATE OR REPLACE FUNCTION shop.rebuild_product(pid bigint) RETURNS void LANGUAGE plpgsql AS $$
DECLARE
  p shop.product;
  prod_terms int[];
BEGIN
  SELECT * INTO p FROM shop.product WHERE id = pid;
  IF NOT FOUND OR p.status <> 'publish' THEN
    DELETE FROM shop.listing WHERE product_id = pid;
    DELETE FROM shop.variant_facet WHERE product_id = pid;
    DELETE FROM shop.page WHERE product_id = pid;
    RETURN;
  END IF;
  IF p.parent_id IS NOT NULL OR p.visibility = 'hidden' THEN   -- page only, not listed
    DELETE FROM shop.listing WHERE product_id = pid;
  END IF;

  -- product-level (non-variation) attribute terms + brand
  SELECT COALESCE(array_agg(DISTINCT t), '{}') INTO prod_terms
  FROM (SELECT unnest(term_ids) t FROM shop.product_attribute WHERE product_id = pid AND NOT for_variations
        UNION SELECT p.brand_term_id WHERE p.brand_term_id IS NOT NULL) x;

  DELETE FROM shop.variant_facet WHERE product_id = pid;
  INSERT INTO shop.variant_facet (variant_id, product_id, term_ids, price, in_stock)
  SELECT v.id, pid, sort(uniq(sort(v.option_term_ids || prod_terms))), shop.effective_price(v), v.stock_status <> 'outofstock'
  FROM shop.variant v WHERE v.product_id = pid AND v.status = 'publish';

  IF p.parent_id IS NULL AND p.visibility <> 'hidden' THEN
  INSERT INTO shop.listing AS l (product_id, slug, name, card, category_ids, term_ids, tag_ids, price_min, price_max,
                           on_sale, in_stock, featured, in_catalog, in_search, menu_order, total_sales, rating_avg, published_at, search)
  SELECT pid, p.slug, p.name,
    jsonb_build_object('id', pid, 'slug', p.slug, 'name', p.name, 'type', p.type,
      'image', (SELECT jsonb_build_object('url', m.url, 'w', m.width, 'h', m.height, 'alt', m.alt, 'lqip', m.lqip)
                FROM shop.product_media pm JOIN shop.media m ON m.id = pm.media_id
                WHERE pm.product_id = pid ORDER BY pm.position LIMIT 1),
      'priceMin', agg.pmin, 'priceMax', agg.pmax, 'regularMin', agg.rmin, 'onSale', agg.on_sale,
      'inStock', agg.in_stock, 'rating', p.rating_avg, 'ratingCount', p.rating_count,
      'swatches', (SELECT jsonb_agg(jsonb_build_object('t', at.id, 'hex', at.swatch_hex) ORDER BY at.menu_order)
                   FROM shop.attribute_term at JOIN shop.attribute a ON a.id = at.attribute_id AND a.kind = 'color'
                   WHERE at.id = ANY(agg.var_terms))),
    COALESCE((SELECT array_agg(DISTINCT a) FROM shop.product_category pc JOIN shop.category c ON c.id = pc.category_id,
              unnest(c.ancestor_ids) a WHERE pc.product_id = pid), '{}'),
    sort(uniq(sort(agg.var_terms || prod_terms))),
    COALESCE((SELECT array_agg(tag_id ORDER BY tag_id) FROM shop.product_tag WHERE product_id = pid), '{}'),
    agg.pmin, agg.pmax, agg.on_sale, agg.in_stock, p.featured,
    p.visibility IN ('visible','catalog'), p.visibility IN ('visible','search'),
    p.menu_order, p.total_sales, p.rating_avg, COALESCE(p.published_at, p.created_at),
    setweight(to_tsvector('simple', p.name), 'A') ||
    setweight(to_tsvector('simple', COALESCE((SELECT string_agg(sku, ' ') FROM shop.variant WHERE product_id = pid), '')), 'A') ||
    setweight(to_tsvector('simple', p.short_description), 'B')
  FROM (
    SELECT COALESCE(min(shop.effective_price(v)) FILTER (WHERE v.stock_status <> 'outofstock'), min(shop.effective_price(v)), 0) AS pmin,
           COALESCE(max(shop.effective_price(v)) FILTER (WHERE v.stock_status <> 'outofstock'), max(shop.effective_price(v)), 0) AS pmax,
           COALESCE(min(v.regular_price), 0) AS rmin,
           COALESCE(bool_or(shop.effective_price(v) < v.regular_price), false) AS on_sale,
           COALESCE(bool_or(v.stock_status <> 'outofstock'), false) AS in_stock,
           COALESCE(array_agg(DISTINCT t) FILTER (WHERE t IS NOT NULL AND v.stock_status <> 'outofstock'), '{}') AS var_terms
    FROM shop.variant v LEFT JOIN LATERAL unnest(v.option_term_ids) t ON true
    WHERE v.product_id = pid AND v.status = 'publish'
  ) agg
  ON CONFLICT (product_id) DO UPDATE SET slug = EXCLUDED.slug, name = EXCLUDED.name, card = EXCLUDED.card,
    category_ids = EXCLUDED.category_ids, term_ids = EXCLUDED.term_ids, tag_ids = EXCLUDED.tag_ids,
    price_min = EXCLUDED.price_min, price_max = EXCLUDED.price_max, on_sale = EXCLUDED.on_sale,
    in_stock = EXCLUDED.in_stock, featured = EXCLUDED.featured, in_catalog = EXCLUDED.in_catalog,
    in_search = EXCLUDED.in_search, menu_order = EXCLUDED.menu_order, total_sales = EXCLUDED.total_sales,
    rating_avg = EXCLUDED.rating_avg, published_at = EXCLUDED.published_at, search = EXCLUDED.search;
  END IF;

  INSERT INTO shop.page (product_id, slug, doc, etag)
  SELECT pid, p.slug, d, md5(d::text) FROM (
    SELECT jsonb_build_object(
      'product', to_jsonb(p) - 'meta' - 'sync_status' - 'woo_modified_gmt',
      'images', (SELECT COALESCE(jsonb_agg(jsonb_build_object('url', m.url, 'w', m.width, 'h', m.height, 'alt', m.alt, 'lqip', m.lqip) ORDER BY pm.position), '[]')
                 FROM shop.product_media pm JOIN shop.media m ON m.id = pm.media_id WHERE pm.product_id = pid),
      'attributes', (SELECT COALESCE(jsonb_agg(jsonb_build_object('id', a.id, 'code', a.code, 'name', a.name, 'kind', a.kind,
                        'forVariations', pa.for_variations, 'visible', pa.visible,
                        'terms', (SELECT jsonb_agg(jsonb_build_object('id', t.id, 'slug', t.slug, 'name', t.name, 'hex', t.swatch_hex) ORDER BY t.menu_order)
                                  FROM shop.attribute_term t WHERE t.id = ANY(pa.term_ids))) ORDER BY pa.position), '[]')
                     FROM shop.product_attribute pa JOIN shop.attribute a ON a.id = pa.attribute_id WHERE pa.product_id = pid),
      -- variant matrix keyed by sorted term ids: client switches variant with zero requests
      'variants', (SELECT COALESCE(jsonb_object_agg(array_to_string(v.option_term_ids, '-'),
                        jsonb_build_object('id', v.id, 'sku', v.sku, 'price', shop.effective_price(v), 'regular', v.regular_price,
                                           'stock', v.stock_status, 'qty', CASE WHEN v.manage_stock THEN v.stock_qty END, 'media', v.media_id)), '{}')
                   FROM shop.variant v WHERE v.product_id = pid AND v.status = 'publish'),
      'categories', (SELECT COALESCE(jsonb_agg(jsonb_build_object('id', c.id, 'slug', c.slug, 'name', c.name)), '[]')
                     FROM shop.product_category pc JOIN shop.category c ON c.id = pc.category_id WHERE pc.product_id = pid)
    ) d
  ) x
  ON CONFLICT (product_id) DO UPDATE SET slug = EXCLUDED.slug, doc = EXCLUDED.doc, etag = EXCLUDED.etag;

  PERFORM nextval('shop.catalog_version');
END $$;

-- ---------- dirty queue: any write-model change marks the product ----------
CREATE OR REPLACE FUNCTION shop.mark_dirty() RETURNS trigger LANGUAGE plpgsql AS $$
DECLARE r jsonb := to_jsonb(COALESCE(NEW, OLD)); pid bigint;
BEGIN
  pid := COALESCE((r->>'product_id')::bigint, (r->>'id')::bigint);   -- product row: id, child rows: product_id
  INSERT INTO shop.dirty (product_id) VALUES (pid) ON CONFLICT DO NOTHING;
  RETURN NULL;
END $$;
CREATE TRIGGER dirty_product AFTER INSERT OR UPDATE OR DELETE ON shop.product FOR EACH ROW EXECUTE FUNCTION shop.mark_dirty();
CREATE TRIGGER dirty_variant AFTER INSERT OR UPDATE OR DELETE ON shop.variant FOR EACH ROW EXECUTE FUNCTION shop.mark_dirty();
CREATE TRIGGER dirty_pcat AFTER INSERT OR UPDATE OR DELETE ON shop.product_category FOR EACH ROW EXECUTE FUNCTION shop.mark_dirty();
CREATE TRIGGER dirty_pattr AFTER INSERT OR UPDATE OR DELETE ON shop.product_attribute FOR EACH ROW EXECUTE FUNCTION shop.mark_dirty();
CREATE TRIGGER dirty_pmedia AFTER INSERT OR UPDATE OR DELETE ON shop.product_media FOR EACH ROW EXECUTE FUNCTION shop.mark_dirty();
CREATE TRIGGER dirty_ptag AFTER INSERT OR UPDATE OR DELETE ON shop.product_tag FOR EACH ROW EXECUTE FUNCTION shop.mark_dirty();

-- worker: called by pg_cron every few seconds and right after an import batch
CREATE OR REPLACE FUNCTION shop.process_dirty(max_items int DEFAULT 500) RETURNS int LANGUAGE plpgsql AS $$
DECLARE r record; n int := 0;
BEGIN
  FOR r IN DELETE FROM shop.dirty WHERE product_id IN (
             SELECT product_id FROM shop.dirty ORDER BY queued_at LIMIT max_items FOR UPDATE SKIP LOCKED)
           RETURNING product_id LOOP
    PERFORM shop.rebuild_product(r.product_id); n := n + 1;
  END LOOP;
  RETURN n;
END $$;


-- reviews -> product.rating_avg / rating_count (the product update marks it dirty -> listing card re-sorted)
CREATE OR REPLACE FUNCTION shop.review_rollup() RETURNS trigger LANGUAGE plpgsql AS $$
DECLARE pid bigint := COALESCE(NEW.product_id, OLD.product_id);
BEGIN
  UPDATE shop.product p SET rating_avg = COALESCE(r.avg, 0), rating_count = r.cnt
  FROM (SELECT round(avg(rating)::numeric, 2) avg, count(*)::int cnt FROM shop.review WHERE product_id = pid AND status = 'approved') r
  WHERE p.id = pid;
  RETURN NULL;
END $$;
CREATE TRIGGER review_rollup AFTER INSERT OR UPDATE OR DELETE ON shop.review FOR EACH ROW EXECUTE FUNCTION shop.review_rollup();
2 · Storefront API: search, product page
-- Storefront API: ONE round trip per screen. Called by the app / web shop through PostgREST RPC (public wrappers, SECURITY DEFINER).
-- p = { "category": 53, "terms": [[5,7],[14]], "priceMax": 100000, "q": "nova", "inStock": true,
--       "sort": "price" | "price_desc" | "popularity" | "date" | "menu_order" | "rating", "limit": 24,
--       "after": { "k": <sort value of the last card>, "id": <product_id of the last card> } }
-- terms: AND between groups (attributes), OR inside a group; all groups must match the SAME in-stock variant.
CREATE OR REPLACE FUNCTION shop.search(p jsonb) RETURNS jsonb
LANGUAGE plpgsql STABLE AS $$
DECLARE
  sort text := COALESCE(p->>'sort', 'menu_order');
  key_col text; dir text;
  w text[] := ARRAY['l.in_catalog'];
  g jsonb; sql text; res jsonb; single int[];
  lim int := LEAST(COALESCE((p->>'limit')::int, 24), 100);
BEGIN
  SELECT c, d INTO key_col, dir FROM (VALUES
    ('price','price_min','ASC'), ('price_desc','price_max','DESC'), ('popularity','total_sales','DESC'),
    ('date','published_at','DESC'), ('menu_order','menu_order','ASC'), ('rating','rating_avg','DESC')) v(s, c, d)
  WHERE v.s = sort;
  IF key_col IS NULL THEN RAISE EXCEPTION 'unknown sort %', sort; END IF;

  IF p ? 'category' THEN w := w || format('l.category_ids @> ARRAY[%s]::int[]', (p->>'category')::int); END IF;
  IF COALESCE((p->>'inStock')::boolean, true) THEN w := w || 'l.in_stock'::text; END IF;
  IF p ? 'priceMax' THEN w := w || format('l.price_min <= %s', (p->>'priceMax')::bigint); END IF;
  IF p ? 'q' THEN w := w || format('(l.search @@ plainto_tsquery(''simple'', %L) OR l.name ILIKE %L)', p->>'q', '%' || (p->>'q') || '%'); END IF;
  IF jsonb_array_length(COALESCE(p->'terms', '[]')) > 0 THEN
    sql := 'SELECT vf.product_id FROM shop.variant_facet vf WHERE vf.in_stock';
    IF p ? 'priceMax' THEN sql := sql || format(' AND vf.price <= %s', (p->>'priceMax')::bigint); END IF;
    -- single-value groups are merged into one "contains all" test (one GIN probe); multi-value groups use "overlaps"
    single := ARRAY(SELECT (g2->>0)::int FROM jsonb_array_elements(p->'terms') g2 WHERE jsonb_array_length(g2) = 1);
    IF cardinality(single) > 0 THEN sql := sql || format(' AND vf.term_ids @> ARRAY[%s]::int[]', array_to_string(single, ',')); END IF;
    FOR g IN SELECT * FROM jsonb_array_elements(p->'terms') LOOP
      CONTINUE WHEN jsonb_array_length(g) < 2;
      sql := sql || format(' AND vf.term_ids && ARRAY[%s]::int[]',
                           (SELECT string_agg((x::text)::int::text, ',') FROM jsonb_array_elements(g) x));
    END LOOP;
    w := w || ('l.product_id IN (' || sql || ')');
  END IF;
  IF p ? 'after' THEN   -- keyset pagination: no OFFSET, page 50 is as fast as page 1
    w := w || format('(l.%I, l.product_id) %s (%L::%s, %s)', key_col, CASE dir WHEN 'ASC' THEN '>' ELSE '<' END,
                     p->'after'->>'k', CASE key_col WHEN 'published_at' THEN 'timestamptz' WHEN 'rating_avg' THEN 'numeric' ELSE 'bigint' END,
                     (p->'after'->>'id')::bigint);
  END IF;

  EXECUTE format('WITH s AS (SELECT l.card, l.product_id, l.%1$I AS k, row_number() OVER (ORDER BY l.%1$I %3$s, l.product_id %3$s) n
                  FROM shop.listing l WHERE %2$s ORDER BY l.%1$I %3$s, l.product_id %3$s LIMIT %4$s)
                  SELECT jsonb_build_object(''items'', COALESCE((SELECT jsonb_agg(card ORDER BY n) FROM s), ''[]''),
                                            ''next'', (SELECT jsonb_build_object(''k'', k, ''id'', product_id) FROM s ORDER BY n DESC LIMIT 1),
                                            ''version'', (SELECT last_value FROM shop.catalog_version))',
                 key_col, array_to_string(w, ' AND '), dir, lim) INTO res;
  RETURN res;
END $$;

CREATE OR REPLACE FUNCTION shop.product_page(p_slug text) RETURNS jsonb
LANGUAGE sql STABLE AS $$ SELECT doc || jsonb_build_object('etag', etag) FROM shop.page WHERE slug = p_slug $$;
3 · Category facets: precomputed table and facets()
-- precomputed facet counts for category landing pages (the most visited listing pages)
CREATE TABLE IF NOT EXISTS shop.category_facet (
  category_id int NOT NULL,          -- 0 = whole shop
  term_id int NOT NULL,              -- 0 = row carrying the price range / product count
  product_count int NOT NULL,
  price_min bigint, price_max bigint,
  PRIMARY KEY (category_id, term_id)
);

CREATE OR REPLACE FUNCTION shop.refresh_category_facets() RETURNS void LANGUAGE plpgsql AS $$
BEGIN
  CREATE TEMP TABLE cf_new ON COMMIT DROP AS
  WITH pt AS (          -- distinct (product, term) pairs of in-stock variants
    SELECT DISTINCT vf.product_id, t FROM shop.variant_facet vf, unnest(vf.term_ids) t WHERE vf.in_stock
  ), lc AS (            -- product -> every category it is shown in (+ 0 = whole shop)
    SELECT l.product_id, c FROM shop.listing l, unnest(l.category_ids || 0) c WHERE l.in_catalog AND l.in_stock
  )
  SELECT lc.c AS category_id, pt.t AS term_id, count(*)::int AS product_count, NULL::bigint AS price_min, NULL::bigint AS price_max
  FROM lc JOIN pt USING (product_id) GROUP BY 1, 2
  UNION ALL
  SELECT c, 0, count(*)::int, min(l.price_min), max(l.price_max)
  FROM shop.listing l, unnest(l.category_ids || 0) c WHERE l.in_catalog AND l.in_stock GROUP BY 1;
  DELETE FROM shop.category_facet;
  INSERT INTO shop.category_facet SELECT * FROM cf_new;
END $$;

-- facets(): category-only requests read the precomputed table; any other filter falls back to the live query
CREATE OR REPLACE FUNCTION shop.facets(p jsonb) RETURNS jsonb
LANGUAGE plpgsql STABLE AS $$
DECLARE cond text := 'l.in_catalog'; res jsonb; cat int := COALESCE((p->>'category')::int, 0);
BEGIN
  IF (p - 'category') = '{}'::jsonb THEN
    SELECT jsonb_build_object(
      'terms', COALESCE(jsonb_object_agg(term_id, product_count) FILTER (WHERE term_id <> 0), '{}'),
      'price', (SELECT jsonb_build_object('min', price_min, 'max', price_max) FROM shop.category_facet WHERE category_id = cat AND term_id = 0),
      'source', 'precomputed')
    INTO res FROM shop.category_facet WHERE category_id = cat;
    RETURN res;
  END IF;
  IF p ? 'category' THEN cond := cond || format(' AND l.category_ids @> ARRAY[%s]::int[]', cat); END IF;
  EXECUTE format($q$
    SELECT jsonb_build_object(
      'terms', COALESCE((SELECT jsonb_object_agg(t, n) FROM (
          SELECT t, count(DISTINCT vf.product_id) n
          FROM shop.listing l JOIN shop.variant_facet vf ON vf.product_id = l.product_id AND vf.in_stock, unnest(vf.term_ids) t
          WHERE %1$s GROUP BY t) x), '{}'),
      'price', (SELECT jsonb_build_object('min', min(price_min), 'max', max(price_max)) FROM shop.listing l WHERE %1$s AND l.in_stock),
      'source', 'live')
  $q$, cond) INTO res;
  RETURN res;
END $$;
