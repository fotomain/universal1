The 8 Constraint Types – Work Breakdown Structure

Scope: the MS Project Task Information > Advanced > Constraint type with its date, and the project option “Tasks will always honor their constraint dates”, for the Gantt chart of kit8/pm. Item A3 of MORE_GANTT_INPUT.html. Planning document – no implementation, nothing in the code was changed.

1. Goal

MS Project gives every auto-scheduled task one of eight constraints. Together with the links they decide where the task goes, and when the two disagree a warning icon appears and the option “always honor constraint dates” decides who wins.

The app has exactly one of them: Start no earlier than (empty = As Soon As Possible), stored in rowJSON.manualStartAt. There is no As Late As Possible, no “Must …”, no “No later than”, no constraint on the finish, and a link that conflicts with the date is not reported. A planner cannot say “this must be finished on 30 June” or “schedule it as late as the successors allow”.

This feature adds the other seven types, the conflict warning, the negative slack that goes with it, and the project option that decides who wins.

Hard constraint: a project that never uses the new types schedules exactly as today. The existing manualStartAt keeps its meaning (Start No Earlier Than); the new UI is behind a project switch that is OFF while never saved.

2. The 8 types (MS Project behavior and the proposal for the app)

Dates: D of a start type is the first day of the task; D of a finish type is the last day of the task (inclusive), the same convention as the Finish field of the task window (the scheduler’s finishMs is exclusive: ef = D + 1 day). With hour / minute / second planning the date carries the time, as manualStartAt does today.

4.2 Who wins: the option “always honor constraint dates”

TypeOption ON (default)Option OFF
ASAP, ALAP, SNET, FNETThe links can only move the task later, which these types allow: no conflict is possible (an ALAP task simply uses its free slack).
MSO, MFOThe constraint wins: the task sits on D even if a predecessor ends later. constraintConflict = 'constraintWins' when the links would have put it later; the link is drawn but is violated.The links win: the task starts at max(D, links); when the links are later than D, constraintConflict = 'linkWins' and the slack is negative.
SNLT, FNLTThe constraint wins: when the links would start (finish) the task later than D, it is placed at D; 'constraintWins'.The links win: ASAP position, 'linkWins', negative slack.

In both cases the task is critical when its slack is ≤ 0; successors always read the dates that were finally used.

4.3 Calendar and edge rules

  • A start D on a non-working day (when the project skips weekends) is moved to the next working day for the placement; the tip says so. Same for the finish types (to the previous working day).
  • A milestone may have any type; its start and finish are the same day, so MSO = MFO there.
  • Dependencies on a stage still expand to leaves (existing rule); a constraint on a leaf inside is respected.
  • Cycles: unchanged; a constraint never repairs a cycle.
  • Project start: a task may be constrained before it (as the SNET can be today only after it); the Gantt time line is widened (risk Z2).
  • Subproject tasks and Manually Scheduled tasks ignore the constraint (their dates come from the subproject or from the user; see the two sibling WBS documents); the constraint block is hidden with a reason text.

4.4 Slack, critical path and the backward pass

Today totalFloatDays is clamped to ≥ 0 (Math.max(0, …) in scheduling.ts) and isCritical means float ≤ 0. Negative slack needs a value below zero, but the clamped field is read by networkModel.ts (tfCal), taskShare.ts, PMProjectTaskInfo.tsx and PMTaskEditModal.tsx. Proposal: keep totalFloatDays as it is and add slackDays (can be negative) for the new texts (“slack −3 d”); the critical flag uses it.

The backward pass keeps its formula and takes the bounds of the table in section 2 as an extra min on the late finish. ALAP is not part of it: it is the extra forward-scheduled pass of section 2 (it uses the successors’ scheduled dates, so free slack, not total slack).

4.5 What each editing action does

ActionResult
Task window: choose type, then dateWrites taskConstraintType + taskConstraintDate (and the manualStartAt mirror for SNET); ASAP / ALAP clear the date; one undo step.
Inline Start cell in the treeAs today: sets SNET with the typed date, empty = ASAP. On a task that has another type the cell asks “Replace the constraint Must finish on … by Start no earlier than …?” (Q3).
Drag a barAs today it writes SNET. On an MSO task the date moves with the bar and stays MSO; on an MFO task the finish date moves and stays MFO; on ALAP / SNLT / FNET / FNLT it becomes SNET (the MS Project result of a drag).
Duration, links, indent, moveUnchanged; the constraint stays and is re-evaluated by the next calculation.
Duplicate task / stageThe copy keeps type and date (as it keeps manualStartAt today).
New project from a project templateThe constraint dates are shifted with the new project start (as manualStartAt is); ASAP / ALAP are untouched.

4.6 Display

  • Task window (PMTaskEditModal): a block “Constraint” with a list of the eight types (SelectItemFromListApp) and a date field (DateInputApp) that is hidden for ASAP / ALAP; today’s “Start no earlier than” field becomes this block while the switch is on.
  • Tree: two optional columns constraintType (“Constraint”) and constraintDate (“Constraint date”), hidden by default, shown only while the switch is on; filter and sort like the other columns. A constraint icon and, on a conflict, a warning icon in the Task name cell (tips: “Must finish on 2026-06-30 · links would finish it on 2026-07-08”).
  • Gantt bar: a small mark at the constrained end (lock for the Must types, left / right bracket for the No earlier / No later types, none for ASAP / ALAP and plain SNET), warning triangle on a conflict, critical color on negative slack.
  • Task info page, share text, hover tip: “Constraint: Must finish on …” and the slack, instead of “start ≥ …”.

7. Acceptance criteria

  • With the switch off, or on and no new type used, dates, slack and critical path are as before and nothing new is written.
  • Each of the eight types places a task as in section 2: ASAP at the earliest, ALAP at its free latest without moving a successor, MSO / MFO on the date, SNET / FNET not earlier, SNLT / FNLT not later when the links allow.
  • With the option ON an MSO task stays on its date although its predecessor ends later; the warning shows both dates; the predecessor’s link is drawn and still moves tasks that are not constrained.
  • With the option OFF the same plan starts the MSO task after its predecessor, the slack is negative, the task is critical and the warning says that the link won.
  • A typed Start in the tree still gives Start No Earlier Than; a dragged auto bar still gives it; an old project reads all its manualStartAt values as SNET without a migration.
  • A stage, a subproject task and a manually scheduled task cannot take a type and say why.
  • Turning the master switch off asks when other types exist and ignores them; turning it on restores them.
  • A version, a project from a template, a task template, a JSON export / import and the MS Project XML keep type and date (the template: shifted / cleaned as 7.3 / 7.4 say).

8. Out of scope

  • Constraints on summary tasks (MS Project applies them to the summary bar and warns about the children) – later, together with manual summary tasks.
  • The deadline date (A5): a marker that never moves a task.
  • Task calendars, resource leveling and the status date; they are other items of MORE_GANTT_INPUT.html.
  • The Planning-Wizard-style dialogs of MS Project that ask before a drag breaks a constraint (the warning icon replaces them).
  • Money plans: Time, Material and Expense lines follow the dates of the task as today.

10. Risks

#RiskHandling
Z1The ALAP pass changes dates of tasks that today are at their earliest; successors could end up violated by a wrong limit.3.4 uses the successors’ scheduled dates and never moves a successor; the table test has a chain case and a check that the project finish does not change.
Z2A date before the project start (or far after the finish) breaks the time-line range and “Fit to screen”.Check how PMGanttSurface takes the range; widen it by the earliest / latest constraint date; test one year before the start.
Z3Two sources for SNET (manualStartAt and taskConstraintType) drift apart.One writer (patchForConstraint), one reader (constraintOf), a test that no command writes manualStartAt alone while the switch is on.
Z4Negative slack reaches code that assumes ≥ 0 (critical (0 d) texts, network view).The audit 1.2 and the separate field of Q5.
Z5A Must date makes the written dates differ from what the links give, so the plan is “wrong” by design after a late predecessor; Post unposts lines as the written day changes.Only the existing unpost-on-date-change rule; the warning icon is the user’s signal; documented in the README (8.3).
Z6The MS Project export of finish constraints gives other dates than MS Project would compute (working hours 08:00–17:00 in the export calendar).7.5 opens the file in MS Project once; the date of a finish type is exported at 17:00.
