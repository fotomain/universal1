Project versions: structure

On the user's command the app stores the full project plan as a version. A version can be restored later, and one or more versions can be compared with the live project on one Gantt chart.

Module kit8/pm/version · SQL kit8/sql/init/done/create_tables.sql section 5b · tests __tests__/pm/version

Tables

Table name = version_ + original table name. Every version table has rowVersionGUID (one value per saved version).

Relations

Deleting a project deletes its versions; deleting a version deletes its child rows (foreign keys with ON DELETE CASCADE).

Access rules

  • Version rows are written only by the RPCs below. Clients have SELECT on all five tables and DELETE on version_project_table.
  • Row level security: a user sees only his own versions (rowOwnerGUID = auth.uid(), child tables through pm_owns_version).
  • No tree, dependency, closure or progress triggers on the version tables: a version never changes after it was saved (only its title).
  • The version tables are not in the realtime publication; the list is re-read after every command.

Save and restore

RPC pm_version_save(p_project, p_title)

  1. Checks that the project belongs to the user; one advisory lock per project.
  2. Version number = highest number of the project + 1.
  3. Copies the project row and the four child tables into the version tables, in one transaction.
  4. Returns the new rowVersionGUID.

Default title in the app: project name + date and time.

RPC pm_version_restore(p_version, p_backup_title)

  1. The app asks first (Yes / No / Cancel).
  2. Saves the current plan as a new version "Before restore <date>".
  3. Deletes the project's tasks (dependencies and Kanban states follow) and Kanban stages.
  4. Writes the version's project data, tasks (parents first), stages, dependencies and Kanban states back with their original rowGUIDs.
  5. Rebuilds the dependency closure and the progress. Returns the rowVersionGUID of the backup.
  6. The app clears the Gantt undo history of the project and re-reads the project.

RPC pm_version_set_title(p_version, p_title)

Renames a version. Delete = DELETE of the version_project_table row (asks first).

Visual comparison

  1. In the Versions view the user checks the versions to compare (at most 4). The choice is saved per project and user in uxuiSettings.checkedProjectVersions.
  2. The app loads the tasks and dependencies of each checked version and schedules them with the same scheduler as the live project, using the start date and calendar stored in the version.
  3. On the Gantt chart the live project is drawn as usual and stays editable. Each checked version is a thin read-only bar under the task bar of the same row, matched by rowGUID.
  4. Each version gets its own color, different from the other versions and from the colors the live project uses (bar color, critical path color, milestone and stage colors, custom task colors). A legend shows color and version title.
  5. The time line is widened so version bars before the project start or after its finish are visible.
  6. Each version card shows the differences to the project now: rows added, removed, moved, changed, and the shift of the finish date in days.

Limits of this release

  • The row height of the Gantt is fixed. One version fits completely under the task bar; with 2 to 4 versions the bars get thinner and the upper ones overlap the lower edge of the task bar.
  • A task that exists only in a version (deleted from the project since) has no row on the Gantt. It is counted as "removed" on the version card.
  • Version bars have no hover details; dependency arrows are drawn for the live project only.

Install

  1. Run kit8/sql/init/done/create_tables.sql in the Supabase SQL editor. It is idempotent and non-destructive: it adds the five version_ tables, the RPCs and the policies.
  2. Until then the Versions view shows a hint and the Save button is disabled; the rest of the app works as before.
  3. Check: SELECT table_name FROM information_schema.tables WHERE table_name LIKE 'version\_%'; returns five rows.
  4. Remove everything: kit8/sql/init/done/delete_tables.sql (drops the version tables and functions too).
