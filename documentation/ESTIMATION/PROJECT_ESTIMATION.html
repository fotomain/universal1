Project estimation

A project can have an estimation: another, ordinary project (project2) in which the user prepares the plan of the work before the real project (project1) starts. Project1 points to it, shows what it adds up to per budget item, and a button copies the whole estimation into project1.

What is new

  • one key project_table.rowJSON.projectEstimationGUID (the link);
  • one tab Estimation in Project settings, right after ROI;
  • three pieces in it: ProjectEstimationGUIDInput, ProjectEstimationTable, FillProjectFromEstimationButton;
  • a read function and a delete function in SQL (PART 57); no new table.

What is reused (nothing is rebuilt)

  • the project search of SelectProjectFromList (useProjectSearchQuery);
  • ReusableTable in local rows mode (like the Fields tab of Monitor01);
  • the planner and the writers of Copy with Tasks (planProjectImport, project_import_tasks, chunks 500 / 250 / 250);
  • the budget item catalog and the plan sums of the task lines (sumForBudget).

ItemRule

DefaultAbsent. Never a default of the organization (defaultProjectSettings): a link is specific to ONE project, so the Estimation tab is not shown in Organization edit → Projects → Settings, and the key is never written there.
Who may be project2Any project the user can read in the active organization (the list is the one of SelectProjectFromList). Not project1 itself (refused in the input and in SQL). Project2 may have an estimation of its own (a chain is only a link, nothing follows it).

Saved withThe Save / OK buttons of the Project settings window, like every other tab (the draft of the window). A new, unsaved project can already choose project2; only Fill needs the saved project.
Project2 deleted / not visibleThe key stays (no trigger rewrites other people's projects). The tab shows "The estimation project is not found or you cannot read it" with the Clear button; the table is empty and Fill is disabled.
Copy project (card menu)The key is copied with the other settings (a copy of project1 has the same estimation). Copy of a read-only project is unchanged.

Read-only project (PART 51)The key cannot change while projectIsReadonly is on (only the switch can). Q1 asks if the owner wants the key exempt.

3 · ProjectEstimationTable.tsx - the summary per budget item

Source of the numbers

The rows are the task lines of project2 (task_line_table: rowJSON.budgetItemTaskLine, sumForBudget, sumVATForBudget, genus = rowParentGUID), summed by budget item. Reason (Q3): an estimation is normally not posted, so the posted plan (task_line_plan_movements) would be empty - and the table must show exactly what Fill will copy, and Fill copies lines.

  • One database call: project_estimation_summary(p_target uuid, p_source uuid) (section 5). Not a read of all lines by the client (a request returns 1000 rows at most; a big estimation has many more).
  • The same call gives the sums of project1 (the column Project now), so the user sees what Fill will change before pressing it.

Columns (ReusableTable local rows, no add / delete, readOnly)

ColumnContent
Budget itemTitle from the catalog (translated title through rowTitle); a line with no budget item goes to one row (no budget item) with a warning icon.
KindCost or Revenue (budgetKind of the genus: Time / Material / Expense = cost, Deliverable = revenue). Header groups (folders): Cost and Revenue.
LinesNumber of task lines of project2 on this item.
EstimateSum of sumForBudget (net) in the budget currency of project2; the header shows the currency code.
VATSum of sumVATForBudget. The VAT basis switch of the reports is not used here (a line has only net and VAT, not the "VAT that is cost" split); the column says so in its tip.
In <currency of project1>Only when the two budget currencies differ: Estimate converted with fx_convert at the latest rate of today (rate type Default). Informational: Fill recalculates the lines at their own rate days.
Project nowThe same sum of project1 (its own unposted + posted lines, sumForBudget), in project1's currency.
Estimate − nowThe difference, in project1's currency.

Total rows and warnings

  • Footer: Total cost, Total revenue, Estimated profit = revenue − cost and Estimated ROI1 = profit / cost (no cost = empty), the same formula as ROI_DOC.html.
  • Above the table, only when true: "N lines have no budget sum" (the project has no budget currency or a rate is missing - the sum counts as 0, never guessed; same wording as the Budgets view) and "N lines have no budget item".
  • Different budget currency of the two projects: a line "Estimate in EUR, this project in USD: Fill recalculates the lines".

4 · FillProjectFromEstimationButton - copy project2 into project1

What is copied

Data of project2Copied?How
Stages, tasks, milestonesyesNew ids, tree paths rebuilt under project1 (planProjectImport), order kept.
Links between the tasksyesOn the new ids; a link to a row outside the copy is dropped.
Task lines (Time / Material / Expense / Revenue)yesNew ids, UNPOSTED (the posting fields are cleared). The user presses "Post unposted tasks" in project1.
Lines of another budget currencycleanedWhen the budget or accounting currency of project1 differs from project2: the budget / accounting sums and the fx snapshot of the copied lines are cleared; sumForContract stays. The user presses Recalculate (Q7).
Project settings of project2 (currencies, calendar, scenarios, custom column definitions)noProject1 keeps its own; the import planner would overwrite them, so Fill passes the settings of project1 as they are (Q5). Custom column values travel with the tasks and show only if project1 has a column with the same id.
Posting, plan / fact registers, documents, time sheets, paymentsnoAs in Copy with Tasks.
Subproject marks, chat, files, BIMnoAs in Copy with Tasks (the link rows and files belong to project2).
Name, owner, read-only switch, projectEstimationGUID of project2noProject1 keeps its identity.

Two modes (asked in the confirm window; only when project1 already has tasks)

Append (default)

The copied rows become new top-level rows after the existing ones. Nothing of project1 is touched. Allowed always.

Replace

After the copy succeeded, the old top-level rows of project1 (with everything below them) are deleted. Offered only when project1 has no posted task and no document (postedTasks = 0 and documents = 0 of the summary call). Otherwise the radio shows it disabled with the reason.

An empty project1 has no choice: the rows are simply written.

Confirm window (ModalAskComponent)

Fill "Hall 12" from "Hall 12 - Estimate"?

  • 24 tasks and stages, 31 links, 11 task lines (27 200.00 EUR cost, 36 000.00 EUR revenue) will be copied. The lines are not posted.
  • ( ) Add after the existing rows of this project   ( ) Replace the existing rows (not possible: 3 tasks are posted)
  • Different budget currency: the sums of the lines are recalculated in USD (press Recalculate).
  • Buttons: Cancel · Fill. While it runs: a progress bar with the steps (read, tasks, links, lines, done) and Cancel; the bar is locked like the export window.

Order of the writes - all or nothing (no data of project1 is lost on a failure)

1 Checkproject_estimation_summary: rights, counts, posted tasks, documents. Read-only project1 stops here.
2 Read & planreadProjectData + readProjectTaskLines of project2, plan with new ids. Nothing is written yet.
3 Write new rowsproject_import_tasks (500 a chunk), links (250), lines (250). The new top-level ids are known from the plan.
4a Replace onlydelete the OLD top-level rows of project1 (project_delete_task_roots).
5 Donerefresh project1 (tasks, tree, Gantt), snackbar "N tasks, M lines copied", hint "Post unposted tasks".
  • A failure in 3: the NEW top-level rows are deleted again (project_delete_task_roots with the ids of the plan), project1 is as before, ErrorModalWindow shows the reason.
  • A failure in 4a (Replace): both the old and the new rows exist; the window says so in words ("the copy is complete, the old rows could not be deleted: ...") - nothing is lost, the user deletes the old ones or retries.
  • Why not "delete first": a failure after the delete would lose the tasks of project1. Why not one SQL function: a link insert costs about 1.4 s per 500 links (cycle check + closure), so a 4000-link estimation would pass the 8 s limit of authenticated; the chunked client path is proven (CAKE1: 1958 tasks).
  • Fill is recorded on project1: rowJSON.projectEstimationLastFill = { at, sourceGUID, mode, tasks, lines } (written after step 5, fresh row first). The tab shows "Last fill: 2026-12-02 10:14, Append, 24 tasks". It is information only; a second Fill is allowed (Append adds the rows again - the confirm window says "Already filled on ...").

Rights

  • Read of project2 = any member who sees it (the summary and the read functions are SECURITY INVOKER, so the existing RLS decides).
  • Write into project1 = the right to create tasks there (project manager / owner: perm_can_in('project_task_table', 'C', project1), the same answer the task writers already use). A user without it sees Fill disabled with the reason.
  • No new profile and no new matrix row (no new table).

Dates

The copied tasks keep the dates of project2, as in Copy with Tasks (Q6). Project1's scheduler runs as usual on the new rows. Shifting the dates to the start of project1 is listed under Not built.

No table, no column, no seed: start1, start3, start4, start5 do not change. The delete file drops the functions (numbered part, reverse order). Docker test kit8/docker/tests/107_project_estimation.sql (one transaction, rolled back).

ObjectKindWhat it does
project_estimation_summary(p_target uuid, p_source uuid)function STABLE, SECURITY INVOKERReturns jsonb: source and target = { currency, items: [{ budgetItemGUID, kind, lines, sumForBudget, vatForBudget, linesWithoutSum }], tasks, links, lines, linesWithoutItem, linesWithoutSum }; plus for the target: postedTasks, documents, readonly, canCreate. Refuses a row that is not a top-level row of that project, a read-only project, and (SECURITY INVOKER) any row the user may not delete.
trg_project_estimation_guardtrigger BEFORE INSERT OR UPDATE on project_tableOnly when projectEstimationGUID changed: refuses the project itself; refuses a value that is not a UUID of an existing project of the SAME organization (checked through a small SECURITY DEFINER helper project_same_organization, because the invoker may not read other users' projects).
