1. Incident Symptoms & Browser Security Block

When loading the web application in browser environments (Firefox / Chrome), the browser halted script loading and displayed the following error log:

Client-Side Security Error (Browser Network & Console) GET /node_modules/expo-router/entry.bundle
GET http://localhost:8081/node_modules/expo-router/entry.bundle?platform=web&dev=true&hot=false&lazy=true&transform.engine=hermes&transform.routerRoot=app&unstable_transformProfile=hermes-stable NS_ERROR_CORRUPTED_CONTENT The resource from "http://localhost:8081/node_modules/expo-router/entry.bundle?..." was blocked due to MIME type ("application/json") mismatch (X-Content-Type-Options: nosniff).
Security Mechanism Explained:
Modern browsers enforce strict MIME-type sniffing prevention through the X-Content-Type-Options: nosniff HTTP header. When Metro encounters a route resolution failure or bundling error during request handling, it responds with an HTTP 500 error payload encoded in JSON (Content-Type: application/json). Because the HTML document requested this resource via a <script> tag expecting application/javascript, the browser immediately blocks execution, returning NS_ERROR_CORRUPTED_CONTENT to protect against script execution vulnerabilities.
