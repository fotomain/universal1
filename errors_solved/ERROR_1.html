1. Incident Symptoms & Browser Rejection

When navigating to the Expo Web application, the browser failed to execute the client script and threw the following console error:

Browser Console Error Firefox / Chromium Security Policy
NS_ERROR_CORRUPTED_CONTENT The resource from "http://localhost:8081/node_modules/expo/AppEntry.bundle?platform=web&dev=true&hot=false&lazy=true&transform.engine=hermes&transform.routerRoot=app&unstable_transformProfile=hermes-stable" was blocked due to MIME type ("application/json") mismatch (X-Content-Type-Options: nosniff).
Mechanism: The browser requested a <script> file expecting application/javascript. Because Metro bundler encountered build/compilation errors, it responded with an HTTP 500 error payload in JSON format (application/json) with strict X-Content-Type-Options: nosniff security headers. Browser security rules blocked this payload from executing as a script, triggering NS_ERROR_CORRUPTED_CONTENT.

2. Root Cause Breakdown

A
Missing Babel Plugin: react-native-dotenv

babel.config.js was configured to use module:react-native-dotenv for @env imports, but the dependency was missing in package.json and node_modules.

Metro DeltaBundler Worker Stack Trace
Error: Cannot find module 'react-native-dotenv' Require stack: - /Users/mgtimber/UNIVERSAL1/expo-app/node_modules/@babel/core/lib/config/files/plugins.js - /Users/mgtimber/UNIVERSAL1/expo-app/node_modules/@expo/metro-config/build/transform-worker/metro-transform-worker.js
B
Expo Router Entry Point Mismatch in package.json

The project uses Expo Router (with plugins: ['expo-router'] and an app/ directory architecture). However, package.json pointed to node_modules/expo/AppEntry.js (which looks for a legacy root App.js that did not exist), instead of expo-router/entry.
